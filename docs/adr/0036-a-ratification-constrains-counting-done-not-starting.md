# ADR-0036: A ratification constrains counting done, not starting

Date: 2026-09-18
Status: Accepted
Tasks: `A1-306`
Follows ADR-0025 (a discretionary order is a field, not a kind of dependency).
Constrains nothing in ADR-0013 (cut sequencing), which keeps its own edges.
Supersedes nothing.

## Context

`blocked_by` is the only dependency edge the model has, and it was being asked to
carry two relationships that behave nothing alike:

- a **producer** edge: this task consumes what the blocker makes, so it genuinely
  cannot start;
- a **ratification** edge: somebody must bless the result before it counts, and
  the work can be built, tested and gated today.

The sixth pilot drew eleven of the second kind as the first. `aplan ready`
reported none of them, **and it was right to**: nothing in the file said which
was meant. Five of those artefacts already existed, were regenerated by a script
and were gated in CI, while the plan called them blocked. That cost two days of
wrong belief (pre-public adoption evidence).

The cost is not the edit. It is that the distinction lived only in the head of
whoever drew the graph, so "this programme is blocked" and "this programme is
mismodelled" looked identical to every command this tool offers.

### The lint the pilot proposed does not work, and this was measured

The pilot named the check that would have caught it: a task whose *only* blocker
is one it does not consume, judged by `paths` overlap. Measured across 5,091
`blocked_by` edges in eight plans on this host:

| | |
|---|---|
| blocker's `paths` overlap the task's | 915 |
| disjoint, the proposed signal | 2,125 |
| one side declares no `paths` at all | 2,051 |
| **live tasks whose every blocker is disjoint** | **927** |

A lint firing on 927 live tasks is not a lint. Worse, it does not find what it
was designed for: `p000000000018`, the plan that *had* the ratification edges,
shows **zero** disjoint edges, while `p003`, which never reported the problem,
shows 1,800. The signal measures plan style -- whether tasks bother declaring
overlapping `paths` -- not what an edge means.

Nothing else in the file distinguishes them either. The meaning is the author's
intent, and intent that is never written down cannot be recovered by inspection.

## Decision

**A new field, `ratified_by`, exactly as ADR-0025 answered the same shape.** When
`blocked_by` is being asked to mean two things, the answer is a second field that
means one of them, not a second kind of edge:

- `ready`, `critical-path`, `why` and `graph` do **not** read `ratified_by`, so a
  ratification can never hide startable work;
- `APLAN046` refuses `done` while a ratifier is unfinished, which is the mirror
  of `APLAN007` for the other half.

**A tag family was rejected on its own terms.** A tag labels a task; ratification
is a relationship with two ends. A tag could record that something needs blessing
and would lose *who blesses it*, which is precisely the edge the pilot drew.

**The release gate is stated rather than inherited.** Re-pointing those eleven
edges risked losing the gate they were also serving, and it survived only because
the release happened to block on the cut holding the chain. An edge doing two
jobs is what this tool should make visible, not what it should rely on, so the
gate now lives in `APLAN046`: the work may proceed, and it may not be called
finished until its ratifier is.

## Consequences

An optional field, absent from every existing task file and added the way
`version_impact` was, so no plan migrates and no adopter is asked to do anything.
A plan that never writes `ratified_by` cannot tell the difference.

`aplan tasks` carries it, because a consumer that can ask what a task waits on
should be able to ask who signs it off. `export --format checklist` names it
among what the shape drops.

What this does not do is find the mismodelled edges that already exist. The
measurement above says no signal in the file can, so the eleven the pilot fixed
were fixed by reading, and the next adopter's will be too -- but they now have
somewhere to put the answer, which is the part that was missing.
