## Why

`revisit_at` and the `due` query shipped for exactly the case an adopter meets first: a task
parked on something outside the plan, where no `blocked_by` edge can ever move it. That change
carried the field into the schema, `tasks --format json`, `show`, MCP and `why`, and its own audit
caught two surfaces that had been ticked without it. One surface was not in that list, and it is
the only one an authoring agent reads: the generated `aplan:begin`/`aplan:end` block.

`crates/aplan-core/src/contract.rs` contains no occurrence of `revisit` or `due`. One adopting
repository authored 128 tasks from that block and parked exactly one, waiting on an installable
aplan release (upstream work, which cannot be an edge under ADR-0029). It gave that task no
`revisit_at`, because nothing the author had read mentioned that the field existed. The field was
found afterwards by grepping `docs/rule-catalogue.md`, where the only place an author meets it is
`APLAN042`'s *fix* text, which is shown only to someone who has already put it on the wrong
status.

The asymmetry is the point, and it is worth stating precisely, because the obvious rule is the
wrong one. `APLAN042` fires when `revisit_at` sits on a `todo` task; nothing fires when a parked
task has none, and nothing should. An earlier measurement found 22 parked tasks, every one waiting
on an unfalsifiable human judgement, and requiring an instant on those would buy fabricated dates.
So the gap is not a missing rule. It is that a field whose entire purpose is to keep an honest park
from going quiet is absent from the document that teaches the idiom, and a warning cannot
substitute for that, because the correct authoring has nothing to warn about.

`APLAN041` exists because a block that has gone stale "teaches a rule the tool would refuse". The
same argument covers a block that is current and incomplete: it teaches an idiom poorer than the
tool's.

## Acceptance criteria

- [ ] the generated contract says a parked task may name a `revisit_at`, and that reaching it means
      a re-read rather than an unblock
- [ ] a test pins the sentence, so the contract and the field cannot drift apart the way `show` and
      `why` did when the field first shipped
- [ ] the contract's field list is audited once against the task schema, and any other field it
      omits is either added or recorded as deliberately withheld
