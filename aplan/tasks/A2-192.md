## Why

The post-release audit of `v0.7.0` (`66ed9997`) uncovered three defects in build-script input
discovery and bind-mounted linked-worktree resolution:

1. **`crates/aplan/build.rs` broke local-vs-hosted release reproducibility when ignored nested
   `target/` directories existed.** `collect_sources` walked the entire workspace root and skipped
   only top-level `target`, `.git`, `aplan`, `docs`, and `ci`. A local checkout that had built the
   standalone `tools/tui-eval` crate contained gitignored `tools/tui-eval/target/` artifacts (`.rs`
   and manifest files). Because `ci/scripts/release.sh` bind-mounts the checkout read-only into
   `/aplan/source`, `build.rs` hashed those ignored files into `APLAN_CACHE_WRITER_IDENTITY`,
   changing the compiled binary digest (`0da205dc...` locally vs `1a86e1c6...` on the clean hosted
   runner). Reproducing `v0.7.0` from a clean worktree without `tools/tui-eval/target/` matched the
   hosted archive (`281e2fbf...`) and binary (`1a86e1c6...`) byte for byte.
2. **`crates/aplan/build.rs` escaped the crate directory during `cargo install` from crates.io.**
   Computing `workspace = manifest.parent().and_then(Path::parent)` assumed `aplan` is always built
   at `<workspace>/crates/aplan`. In a packaged registry build
   (`$CARGO_HOME/registry/src/index.crates.io-.../aplan-0.7.0`), `parent().parent()` resolves to
   `$CARGO_HOME/registry/src`, walking every unrelated crate in the user's Cargo cache (or `/` if
   unpacked one directory below root).
3. **`plan_base` in `aplan-evidence` trusted a container-external `repo.workdir()` on bind-mounted
   linked worktrees.** When `TAG=v0.7.0 ci/scripts/release.sh` ran from a linked Git worktree
   mounted at `/aplan/source`, libgit2 reported the host worktree path recorded in
   `.git/worktrees/<name>/gitdir`, which did not contain `/aplan/source`. `git_path` failed to strip
   that prefix, causing `aplan version` to read zero historical task statuses at the release tag.

## Acceptance criteria

- [x] `crates/aplan/build_support.rs` restricts workspace cache-writer identity inputs to root
      `Cargo.toml`, root `Cargo.lock`, and product crates under `crates/` (excluding `aplan-e2e`
      and skipping `target`, `.git`, `tests`, `benches`, `examples`, `dist`, and `llvm-cov-target`
      at every depth)
- [x] packaged standalone builds outside `<workspace>/crates/aplan` collect inputs strictly inside
      `CARGO_MANIFEST_DIR` and never walk parent or sibling directories
- [x] `crates/aplan/build.rs` watches `CARGO_MANIFEST_DIR` and `CARGO_PKG_VERSION` and normalizes
      relative path separators
- [x] `aplan-evidence` falls back to `repo_root` when `repo.workdir()` does not exist or does not
      contain `repo_root`
- [x] regression tests cover nested `tools/tui-eval/target/` and unrelated workspace directories,
      product-source sensitivity, standalone packaged-crate isolation, and bind-mounted linked
      worktree base resolution
