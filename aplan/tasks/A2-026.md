## Why

Reported in #33 (item 1). `check-docs` promises to check that a document names tasks that
exist, but it only recognises ids that carry digits. A document naming `` `ABC-999` `` is
reported; `` `M-oen` `` (a typo of the milestone `M-one`) and a release id such as `R-v9` pass.
The shapes of the ids a plan actually uses are known from the plan, so a word can be matched
against them. The scanner reads every word of a document, fenced blocks and links included, not
only backticked tokens.

The report notes that this changes what passes, and `check-docs` has no warning tier: a newly
recognised unknown id fails the gate. Widening the match also widens the cross-plan false
positives that A2-163 exists to remove, a deliberate reference to another plan's id read as a
typo of this one; both tasks change the id vocabulary in `crates/aplan-interop/src/docs.rs`, so
they have to agree on what a shape is.

## Acceptance criteria

- [x] a word shaped like one of the plan's own id conventions, including milestone and release
      ids without digits, is checked against the plan
- [x] an unknown id of such a shape is reported with a did-you-mean when a close match exists
- [x] ordinary words that match no id convention are not reported
- [x] the change is release-noted as one that can fail a document that passed before, or is
      opt-in, and the CHANGELOG entry says which
- [x] a comment on #33 records item 1 done, citing this task
