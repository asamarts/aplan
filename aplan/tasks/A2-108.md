## Why

A timestamp can mean when work happened, when a person made a claim, when aplan accepted the
claim, or when Git first observed it. Collapsing those meanings would make a precise-looking
recent-completions report less trustworthy than the current unknown answer.

Record the durable semantics before adding a field or command.

## Acceptance criteria

- [x] an ADR defines `closed_at` as the recorded close transition, not evidence of real-world
      completion
- [x] encoding, precision, timezone normalization, no-backdating and import validation rules are
      explicit
- [x] done, dropped, amend, restamp, import and manual/legacy cases each have a disposition
- [x] milestones are distinguished from completed work, and the default completed-task view does
      not silently mix release checkpoints or dropped work into its answer
- [x] `recorded`, `history_first_seen` and `unknown` provenance cannot be confused in storage or
      typed output; a preserved imported instant cannot become an indistinguishable local record
- [x] transition candidates, commit-time choice, merges, reverts, repeated transitions, skewed
      clocks, incomparable candidates, ties, unknown values and shallow/no-repository behavior are
      explicit
- [x] history policy distinguishes automatic, forbidden and required inference plus complete,
      incomplete, bounded and unavailable results without calling an inferred timestamp exact;
      completeness is scoped to one named basis revision and its reachable history
- [x] the ADR states that timestamp-plus-id sorting is a deterministic report order, not an exact
      causal sequence across concurrent closes or Git branches, and assigns exact event history to
      a future event-log design rather than fabricating it here
- [x] time-bound inclusivity, reversed ordering, equal/unknown timestamps and pagination stability
      have exact semantics shared by CLI, MCP and TUI
- [x] the decision cross-references `A2-063` and keeps lifecycle chronology distinct from measured
      focus time, elapsed duration and external wait
- [x] compatibility and migration preserve existing done tasks without inventing timestamps

## Why it is `untestable`

This task records a data-model and migration decision. Later field, history and command tests
prove the implementation, but cannot prove the semantic tradeoff itself.
