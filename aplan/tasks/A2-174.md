## Why

One adopting repository restamped a done task with the tests that now back its claim. One of
them runs a real process lifecycle once per catalogued operation, parametrized over 148 cases.
`aplan test list` lists each case by its full name, and `verify` refuses the bare test name with
`APLAN013`, because no runner lists it. Refusing the bare name is right: it is not something a
runner can run.

The gap is what a citation can say. The claim the test backs is "all 148", and the only
accepted citations are single cases, so the author had three bad choices: cite one case, which
claims less than the proof; cite all 148, which buries the task's evidence; or cite a different,
unparametrized test. The repository cited a substitute, and nothing in the plan records that the
real proof was the parametrized test.

## Acceptance criteria

- [ ] one citation form means "every case a runner lists for this test", resolved to the full
      listed set when `verify` runs, and the decision on its spelling is recorded in `HLD.md`
- [ ] such a citation fails when the set is empty, and under `--execute` reports each failed case
      by its full name
- [ ] a bare test name that no runner lists is still refused with `APLAN013`, and the fix text
      names the new form when cases of that test are listed
- [ ] tests cover a parametrized test with several cases, an empty set and one failing case
