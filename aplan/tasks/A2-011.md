## Why

The public repository can build and attach one verified Linux artifact to a GitHub release, but it
does not publish the CLI to crates.io and has no complete transaction joining workspace package
publication, registry visibility, GitHub assets, and rerun behavior. The first public crates.io
release also has a one-time bootstrap constraint: trusted publishing can be configured only after
each new crate exists. Publish v0.5.0 without a long-lived CI secret, then leave a tested OIDC path
for every later release.

## Acceptance criteria

- [x] the complete public increment is re-audited and all discovered release blockers are fixed
- [x] v0.5.0 has one curated changelog section, release manifests, and a locked graph that agree
- [x] every publishable workspace crate packages cleanly and publishes in dependency order
- [x] publication waits for each internal crate to become resolvable before publishing dependents
- [x] rerunning the workflow proves matching registry versions and assets instead of failing or
      silently replacing content with different bytes
- [x] subsequent tag releases use crates.io trusted publishing from the protected GitHub release
      environment and retain no long-lived crates.io token in repository automation
- [x] the corrective v0.5.2 tag source passes the complete local and hosted release profiles, and
      the installed crates.io CLI plus the GitHub release artifact both identify as v0.5.2

## Release result

- Source: `59306b06db69c1cac691bd732b8d531411b3c831`, tagged `v0.5.0` after the exact
  tree passed the local release profile and artifact build.
- Registry: all ten workspace packages published as 0.5.0 in dependency order. Each package has
  sole owner `asamarts`, exactly one trusted publisher bound to `asamarts/aplan`, `release.yml`, and
  the protected `release` environment, with `trustpub_only` enabled.
- Artifact: the local release archive has SHA-256
  `c4f7dacf100d415c379cf8cf85c34815f7e817880c467be94adbf7818b26a823`. The public
  GitHub release serves those exact bytes; a downloaded archive is a one-file static PIE that
  reports 0.5.0 and advertises the TUI. A fresh locked crates.io install reports `aplan 0.5.0` and
  its generated facts identify version 0.5.0.
- Automation audit: the first tag run exposed the repository Actions allowlist omitting the pinned
  crates.io OIDC action. The allowlist now admits only GitHub-owned actions plus
  `rust-lang/crates-io-auth-action@*`, while repository-wide full-SHA pinning remains required. Its
  retry then exposed a circular pin gate: the same source passed before its tag existed and failed
  once the tag made 0.5.0 the newest release. The gate and runbook now require a release tree's own
  pins before tagging. Corrective v0.5.1 passed that gate and every hosted check before coverage,
  where the clean runner exposed that release preparation omitted `cargo-llvm-cov`; no artifact,
  registry authentication, package publication, or GitHub release step ran. Corrective v0.5.2
  composes coverage and publication preparation. The successful corrective run recorded below
  exercised the complete hosted OIDC path.

## Corrective release result

- Source: `04b34a9be98b10e4ffbd1877632869b04eb527ad`, annotated tag `v0.5.2`.
- Hosted transaction: <https://github.com/asamarts/aplan/actions/runs/41751133111> passed all
  release gates, built the static artifact, authenticated to crates.io through OIDC, published all
  ten packages in dependency order, and created the final GitHub release.
- Registry: every 0.5.2 package is visible, unyanked, checksum-addressed, and owned solely by
  `asamarts`. The fresh locked install reports `aplan 0.5.2`, advertises `build.tui`, and exposes
  the expected 218 behaviours, 48 commands, 57 rules, and 13 MCP tools.
- Artifact: the public archive has SHA-256
  `689d65309394a45e34f5e3b9cf7de3003534a357e534f78fffcfa8c88230cebe`; its adjacent checksum
  agrees. The one-file archive contains a static PIE whose binary SHA-256 is
  `bbc8fb55724a5998a5dfb1c33e7bf677182ac3141e3d25903ddcba6cbeecd031`, reports 0.5.2, and
  advertises the TUI capability.
- Audit follow-up: a local exact-source archive did not match the hosted bytes even though both
  binaries passed their identity checks. `A2-012` records the precise digests and owns pinning the
  native artifact environment; this release task does not conceal that separate failed claim.
