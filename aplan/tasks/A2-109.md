## Why

Completion order needs a plan-owned instant. It must be written by the same successful guarded
mutation as status and evidence; a clock read before a refused close or a restamp that changes
the original instant would produce false history.

## Acceptance criteria

- [x] the task schema carries the optional normalized close record that `A2-108`'s ADR defines, and
      a rule rejects invalid values, non-done use and any provenance combination the schema alone
      cannot express
- [x] every constructor, exporter, importer and supported transition to `done`, including milestone
      closure, has an explicit timestamp/provenance behavior without changing dropped work
- [x] successful close writes status, evidence, stamps, release data and time atomically
- [x] refused close writes nothing, while amend and restamp preserve the original close time
- [x] ordinary close cannot backdate or overload report `--at`; any import that preserves a source
      timestamp validates and durably labels its provenance under the ADR
- [x] tests use an injected clock and cover offsets, precision, pre-epoch/impossible values,
      same-instant closes, competing writers, refused duplicate retries and legacy absence
- [x] a close retry after snapshot contention samples or preserves time according to one documented
      rule, and only the successfully published transition can introduce the record
- [x] every new rule has crate-local message/instruction assertions, driven fires/silent scenarios,
      catalogue/README/changelog entries and generated schemas that agree
- [x] HLD and upgrading guidance explain optional legacy absence and the non-causal tie-break order
- [x] the existing close behavior change has a named `Behaviour` and executable proof
