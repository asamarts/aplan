## Why

Found in an adopting repository. `cut_label` reads the milestone's tags, so it gives an empty
string for a milestone tagged only `milestone`. Generic reproducer: `M-one` is tagged only
`milestone` and is `blocked_by` its members `ABC-001`..`ABC-003`, while `ABC-004` belongs to no
cut. `aplan tasks` shows a blank cut for every member of `M-one` and `-` for `ABC-004`, which reads
the wrong way round; `--format json` gives `"cut": ""`, and `aplan show ABC-001` prints
`cut  (M-one)`. The effort column prints with `{:>5.1}`, so `effort_days: 0.25` reads `0.2`.

## Acceptance criteria

- [ ] a member of a cut whose label is empty shows the milestone's id, in `tasks`, `show` and the
      JSON.
- [ ] an effort of 0.25 prints as `0.25` wherever a single task's effort is printed. Totals are
      unchanged.
- [ ] tests pin both.
