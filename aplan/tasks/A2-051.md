## Why

Reported in #30; implements `ADR-0069` (`A2-050`). After a heading rename, a trace that resolved to
the heading silently resolves to a table row with the same slug, and no error says the task now
traces a different element kind.

## Acceptance criteria

- [x] `ADR-0069` is implemented: `aplan-core` classifies resolved trace anchors as `heading`,
      `row`, or `node` while preserving `ADR-0015`'s heading-first precedence
- [x] open tasks (`verify`) compare `(kind, hash)` at the task's review baseline against `HEAD` and
      report kind retargeting (`heading` <-> `row`) as a dedicated blocking error (not an
      advisory-capable `APLAN045` warning), while leaving same-kind content edits as `APLAN045`
- [x] newly written `trace_fingerprints` (`close`, `close --restamp`, `supersede`) store additive
      kind-tagged values (`heading:<16-hex>`, `row:<16-hex>`, `node:<16-hex>`) within the existing
      `BTreeMap<String, String>` schema; legacy bare `<16-hex>` stamps remain accepted with zero
      migration churn
- [x] closed tasks (`check`, under `detect_drift`) with kind-tagged stamps report kind retargeting
      as the same dedicated blocking error (even if `APLAN018` is advisory), while leaving same-kind
      content edits as `APLAN018`
- [x] regression tests reproduce #30 for both `heading -> row` and `row -> heading` on open and
      closed tasks, cover legacy bare-hex stamp compatibility, register the new error rule (with
      end-to-end fires/silent coverage) and update `docs/rule-catalogue.md`, `docs/upgrading.md`,
      `facts.json`, and `CHANGELOG.md`
- [x] #30 is closed
