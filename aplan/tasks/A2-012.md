## Why

The v0.5.2 release download audit compared the hosted archive with an archive built locally from
the exact tagged commit. Both static binaries identify as 0.5.2 and expose the expected
capabilities, but their sizes, build ids, binary digests, and archive digests differ. Fixed tar
metadata and Rust path remapping do not make native dependency compilation reproducible when the
release transaction leaves the host C toolchain and related build inputs unpinned. The release
script currently promises byte-comparability across builders, so this is a failed product claim,
not an optional hardening improvement.

## Acceptance criteria

- [x] artifact construction runs inside one immutable, checksum-pinned environment whose Rust,
      musl, C compiler, linker, archive, and compression inputs are part of the reviewed source
- [x] direct and hosted release entry points use the same construction path and refuse an
      unpinned or mismatched build environment
- [x] two clean builds of the same committed source in independent workspaces produce identical
      binary and archive SHA-256 digests
- [x] the release contract and tests state the exact reproducibility boundary without claiming
      more than the implementation proves
- [ ] the change-aware and complete validation profiles pass from the resulting public source
