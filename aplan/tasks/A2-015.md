## Why

ADR-0066 and `A2-014` make the release archive independently attributable to this repository,
workflow, source and hosted builder, and the protected staging run proved that path. The published
composite Action still checks only the SHA-256 file downloaded beside the archive, however. That
detects transfer corruption but does not use the new independent provenance before executing the
binary. The first attested release should make verification part of the ordinary adoption path,
not leave it as an optional command only careful consumers run.

The repository also needs to turn the validated `0.6.0-dev` source into one immutable release,
prove every registry and GitHub output against that source, and then return `main` to a distinct
development version without moving the tag or replacing published bytes.

## Acceptance criteria

- [x] the composite Action verifies every release from v0.6.0 onward against the publishing
      repository, `release.yml`, exact tag, SLSA provenance predicate, GitHub OIDC issuer and a
      GitHub-hosted runner before extraction; the finite historical releases through v0.5.2 keep
      an explicit documented checksum-only exemption
- [x] executable tests cover the attested and historical paths, malformed tags, checksum failure,
      exact verifier arguments and the requirement that provenance succeeds before extraction
- [x] the release source has one empty `Unreleased` section, a dated v0.6.0 section, matching
      workspace and lockfile versions, and every current install pin names v0.6.0
- [x] the exact protected tag source passes local and hosted release profiles, then publishes all
      ten crates, one archive, one checksum and one keyless attestation per successful attempt
      after independent approval
- [x] a fresh locked crates.io install and the GitHub Action report v0.6.0; archive checksum,
      binary, tag, source, registry packages, attestation bundle and Rekor entry all agree
- [x] the release transaction is safely rerunnable without replacing bytes, and `main` advances
      to the next `-dev` version with the immutable v0.6.0 result recorded here

## Release audit record

PR <https://github.com/asamarts/aplan/pull/15> received an independent approval and rebase-merged
the release source as `2fe1aee9fb3f7ef66b30ffb53fe9b5ba8ab99df3`. Annotated tag `v0.6.0`
has tag-object identity `d1acfe30e382d87caf9396abafb243a795ae3a3d` and resolves to that exact
commit. The local release profile passed all 11 gates with 3,629 tests, eight deliberate skips,
383 of 383 CLI members exercised, all 12 crate coverage floors and whole-plan verification of 15
tasks with zero warnings. Hosted release run
<https://github.com/asamarts/aplan/actions/runs/41920343212> independently repeated that profile on
the tag source. Its first attempt encountered Debian snapshot HTTP 503 and 504 responses while
constructing the artifact and stopped before attestation, registry authentication or publication.
The independently approved second attempt completed the transaction.

All ten workspace packages are published as 0.6.0, unyanked, owned only by `asamarts`, and carry
registry checksums matching fresh package downloads. Their trusted-publishing metadata names the
same repository, release run and source commit. A fresh isolated `mbx install --locked aplan
--version 0.6.0` from crates.io completed successfully and reports `aplan 0.6.0` with the TUI
capability.

The stable GitHub release is
<https://github.com/asamarts/aplan/releases/tag/v0.6.0>. Its one archive has SHA-256
`b2b1d33e689349f3d0c558027f37583a2eb42a8f176c8adeeccfa4c8f8680eea`; its adjacent checksum,
GitHub asset digest and independently reproduced local archive agree. The archive contains one
static PIE executable with SHA-256
`554b0cac72b083cf9ee8a309b0761e6d82ca714f456b09d52474cced56e12b16`, reports 0.6.0,
advertises the TUI and identifies the tagged source. GitHub stores the publication attempt's
attestation at <https://github.com/asamarts/aplan/attestations/63796506>, with Rekor log index
<https://search.sigstore.dev?logIndex=3692047047>. Strict verification binds the archive to
`asamarts/aplan`, `release.yml`, `refs/tags/v0.6.0`, SLSA v1, GitHub's OIDC issuer and a
GitHub-hosted runner.

## Rerun and adoption record

Independently approved attempt 3 of the same release run passed the complete profile again,
rebuilt the identical archive, checksum-compared every existing registry package, and downloaded
and byte-compared both existing GitHub assets. The release asset creation and update timestamps
remain those of the original publication. The rerun added the expected immutable provenance for
its own build at <https://github.com/asamarts/aplan/attestations/63809580>, with Rekor log index
<https://search.sigstore.dev?logIndex=3692103494>; both attestations satisfy the strict consumer

and `verify` with a binary that reported 0.6.0. The independently approved PR passed Linux,
Windows, macOS and CodeQL and merged as `b7774c07d6d1042f7f49ca3fe30140cd262193fa`.
