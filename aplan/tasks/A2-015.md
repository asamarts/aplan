## Why

ADR-0066 and `A2-014` make the release archive independently attributable to this repository,
workflow, source and hosted builder, and the protected staging run proved that path. The published
composite Action still checks only the SHA-256 file downloaded beside the archive, however. That
detects transfer corruption but does not use the new independent provenance before executing the
binary. The first attested release should make verification part of the ordinary adoption path,
not leave it as an optional command only careful consumers run.

The repository also needs to turn the validated `0.6.0-dev` source into one immutable release,
prove every registry and GitHub output against that source, and then return `main` to a distinct
development version without moving the tag or replacing published bytes.

## Acceptance criteria

- [ ] the composite Action verifies every release from v0.6.0 onward against the publishing
      repository, `release.yml`, exact tag, SLSA provenance predicate, GitHub OIDC issuer and a
      GitHub-hosted runner before extraction; the finite historical releases through v0.5.2 keep
      an explicit documented checksum-only exemption
- [ ] executable tests cover the attested and historical paths, malformed tags, checksum failure,
      exact verifier arguments and the requirement that provenance succeeds before extraction
- [ ] the release source has one empty `Unreleased` section, a dated v0.6.0 section, matching
      workspace and lockfile versions, and every current install pin names v0.6.0
- [ ] the exact protected tag source passes local and hosted release profiles, then publishes all
      ten crates, one archive, one checksum and one keyless attestation after independent approval
- [ ] a fresh locked crates.io install and the GitHub Action report v0.6.0; archive checksum,
      binary, tag, source, registry packages, attestation bundle and Rekor entry all agree
- [ ] the release transaction is safely rerunnable without replacing bytes, and `main` advances
      to the next `-dev` version with the immutable v0.6.0 result recorded here
