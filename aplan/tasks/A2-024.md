## Why

Reported in #29. A typo in `policy[].when` silently produces a rule that applies to nothing,
and an evidence policy that applies to nothing looks exactly like one that passed:
`when: {cut: [M-noon]}` for the milestone `M-one`, or `when: {tag: [kind-imql]}` for the
plan's `kind-impl`, both pass `check`. An `owners` typo, by contrast, is refused with a
did-you-mean (`APLAN056`), so the tool already treats this class of mistake as worth
catching.

A tag that no task carries yet can be intended; declaring it in a `tag_families` entry is the
way to say so.

## Acceptance criteria

- [ ] `check` warns when `policy[].when.cut` names neither an existing milestone id nor a cut
      label, since the selector matches either
- [ ] `check` warns when `policy[].when.tag` names a tag that no task carries and no `tag_families`
      entry declares
- [ ] both warnings offer a did-you-mean when a close match exists
- [ ] the rule follows the full rule checklist: a fires and a silent scenario, a unit test in the
      raising crate, the generated catalogue and facts
- [ ] #29 is closed
