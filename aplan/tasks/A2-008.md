## Why

The first push to the reconstructed public repository supplied GitHub's forty-zero `before`
object ID. The development launcher passed that sentinel to the selector and later tried to
resolve it as a commit, so the otherwise valid initial CI run failed with `Needed a single
revision`. A branch with no base cannot be narrowed honestly; validate the checked-out source with
the complete profile instead.

## Acceptance criteria

- [x] a forty-zero or sixty-four-zero base is recognized only in paired base/head mode
- [x] the initial-push head must resolve to the checked-out commit before any gate runs
- [x] an initial push runs the complete validation profile and records the checked-out source
- [x] ordinary base/head selection and the explicit full-profile rollback keep their behavior
