## Why

Reported in #56. When a later task deletes a file cited as `file` evidence by an already-closed
task, `aplan close` on the deleting task says nothing, and a subsequent `aplan verify` fails with
`APLAN015` whose fix text says:

```text
Point the `file` evidence at a path that exists at the cited rev (or at HEAD).
```

A `file` citation carries no revision in either `aplan close --evidence file:<path>` or the task
schema, so "the cited rev" is not something an author can write. Discovering the broken citation
only after closing the deleting task also shifts the repair out of the commit that caused it.

## Acceptance criteria

- [x] `APLAN015`'s fix text for `file` evidence names only remedies a `file` citation actually
      supports (re-pointing at the successor path at `HEAD` or replacing the citation with
      `aplan amend`), and `docs/rule-catalogue.md` is updated to match
- [x] `aplan close` checks whether the commit or tree state breaks any closed task's `file`
      citation (or warns naming each affected closed task and deleted path before/on close)
- [x] regression tests cover a deleted cited file through both `verify` (`APLAN015` message and
      fix text) and `close`
- [x] #56 is closed
