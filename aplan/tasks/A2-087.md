## Why

`APLAN029` reports a declared `tag_families` entry that no task carries: a family nothing uses is
either a gap or a typo, and the rule says so. One adopting repository hit it and fixed it by
assigning its `domain` family to the tasks that belonged in it.

`evidence.exempt_tags` has no such rule. The same repository declared
`[milestone, historical-record, untestable]`, wrote a paragraph in `.aplan.yml` explaining that 18
closed work streams were in the `historical-record` position, reported upstream that the gap had
been "converted into a tagged loan", and **no task carried the tag**. Nothing said so for a day.
The exemption was real policy, written down, reasoned about, and inert.

The asymmetry is what makes this worth a rule rather than a note. An exempt tag is a *hole in the
evidence gate*: `milestone`, `historical-record` and `untestable` each name a case where
`require_min_strength` does not apply. A declared hole nothing uses is the one kind of dead config
that is dangerous in both directions. Either it is a typo, in which case the tasks meant to claim
the exemption are silently failing some other way, or it is a loan nobody is carrying, in which
case the plan looks more proved than it is.

`untestable` is the counter-example that keeps this a warning rather than an error: aplan's own
vocabulary teaches it, and an adopter who declares it so the first task needing it finds it legal
is doing something reasonable. So the rule wants the `APLAN029` shape (advisory, naming the tag,
fixable either by using it or by removing it) and not a refusal.

## Acceptance criteria

- [ ] a declared `evidence.exempt_tags` member no task carries is reported, at the advisory tier
- [ ] the message says that whether it is a typo or an unused exemption cannot be guessed, and
      offers both fixes
- [ ] a test covers the case that made this visible: a tag declared, documented in a config
      comment, and carried by nothing
