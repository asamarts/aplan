## Why

An adopting repository measured a cold `aplan verify` at 608.4 seconds and a feature-mismatched
warm run at 232.9 seconds. Its four configured Cargo runners each list tests by building a test
target, so the plan job became more expensive than the repository's full Linux product job, hit a
ten-minute timeout and fought that job over incompatible target artifacts. A structural `check`
still took 0.1 seconds; the cost is provider discovery, not plan validation.

The current product has more machinery than the adopter's request accounted for. Receipt-backed
verification (ADR-0057) can consume complete current test observations without starting providers,
and incremental refresh (ADR-0058) can select affected provider work while retaining a whole-plan
verdict. This task must test those existing boundaries against the measured shape before adding a
new flag. A mode that quietly omits `test` citations and exits as though `verify` completed would
weaken the evidence gate rather than speed it up; if a deliberately partial mode is still useful,
its authority, exit status and unresolved inventory must make that distinction machine-readable.

## Acceptance criteria

- [ ] reproduce the measured shape (several Cargo runners whose listing compiles test targets) from
      an immutable source with cold, dependency-warm, feature-mismatched and fully warm samples;
      report listing/build, queue, execution and exact-plan resolution separately with
      deterministic provider/process counts
- [ ] evaluate current receipt-backed verification and incremental refresh first, including the
      orchestration needed to reuse an existing CI test job, artifact authentication, feature-set
      identity and the cost of producing rather than merely consuming each receipt
- [ ] if current receipts solve the product boundary, document and test one complete GitHub and
      one provider-neutral adoption path; keep direct execution as a scheduled/release oracle and
      make the fast path discoverable from ordinary `verify` guidance
- [ ] if an additional deferred-kind mode is admitted, it cannot report the same completeness or
      success contract as whole-plan verification: human and versioned machine output name every
      deferred citation/kind, exit semantics are explicit, and no stale or partial observation is
      described as resolved
- [ ] catalogue discovery never runs the same configured provider more than once per identified
      observation, and several Cargo runners cannot accidentally serialize redundant workspace
      compilation or invalidate one another through an implicit shared target directory
- [ ] progress and timeout output identify the active provider and distinguish compilation from a
      hung resolver without placing terminal prose on machine stdout
- [ ] hostile, stale, partial, ambiguous and feature-mismatched receipt/listing controls fail
      closed; a mutation test proves that skipping provider work cannot manufacture a clean
      authoritative verdict
- [ ] `docs/design/evidence-gate-performance.md` records the measured disposition, selected
      integration and what work still runs elsewhere rather than presenting moved compilation as
      eliminated work
