## Why

Filed by `A2-081` (`ADR-0068`). When an adopter running a `-dev` build hits an unknown key in
`.aplan.yml` or an unknown field in task frontmatter, the version string alone (`0.8.0-dev`) cannot
tell two development builds from `main` apart. Directing same-version development users to
`aplan facts --identity` (alongside `aplan facts`) lets them immediately compare `source`,
`facts_sha256`, and `binary_sha256` on builds that support it, without claiming an older binary can
diagnose a capability invented after it.

## Acceptance criteria

- [x] unknown `.aplan.yml` key errors in `crates/aplan/src/lib.rs` retain the leading typo

- [x] unknown task frontmatter field errors (`APLAN001`) in `crates/aplan-core/src/load.rs` name
