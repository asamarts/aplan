## Why

Reported in #33 (item 6). With a policy requiring `test` evidence for some tasks and no test
runner configured, `close --evidence test:no_such_test_anywhere` succeeds. `close`, `check`
and `verify` each print an honest note that the citation is unchecked, and `vacuity` shows
the rule as not run, but under `deny_warnings` nothing fails. A repository that believes it
requires tests does not learn that it has stopped doing so.

## Acceptance criteria

- [ ] `check` warns when the top-level `evidence.require_min_strength` or a `policy[]` entry
      requires an evidence kind that no configured resolver can resolve (for example `test` with
      no runner)
- [ ] the warning names the policy entry, or `evidence.require_min_strength`, and the missing
      configuration, and the existing `vacuity`
      explanation stays consistent with it
- [ ] the rule follows the full rule checklist (fires and silent scenarios, unit test, generated
      catalogue and facts)
- [ ] a comment on #33 records item 6 done, citing this task
