## Why

Reported in #27. When `aplan inbox promote` is refused (for example a promoted task would
lack `effort_days` under `deny_warnings`), the report says `refused` on its first line and
`state: promoted` a few lines down. Nothing was written and the capture is still `open`. A
script reading the field, or an agent reading the middle of the report, gets the wrong
answer.

The renderer prints the record it is given. `finish_capture_promotion_with`
(`crates/aplan/src/lib.rs`) builds the report from the predicted promotion and passes that same
record when the write is refused, so the record shown is one that was never written. A unit test
in `aplan-output` renders a hand-built promoted record for every outcome, refused included, so
nothing pins the state a refusal really leaves.

## Acceptance criteria

- [ ] a refused promotion reports `state: open` (the state on disk), and if the would-be state is
      shown it is labelled as such, for example `would become: promoted`
- [ ] `--format json` reports the same real state for a refused promotion
- [ ] an integration test reproduces #27 for a dry-run refusal and for an applied refusal, and
      the `aplan-output` unit test renders the record each outcome really has
- [ ] #27 is closed
