## Why

Pretty output is useful only if generated Markdown, JSON and raw-source workflows remain exact.
Every CLI Markdown-bearing output needs an explicit semantic disposition rather than a TTY guess;
the TUI sink is independently owned by A2-120.

## Acceptance criteria

- [ ] human `show --body` uses the renderer with bold/styled headings, aligned tables and readable
      code
- [ ] an explicit raw-body route writes only the stored body bytes with a documented final-newline
      rule, refuses incompatible presentation flags, and JSON preserves the exact body string;
      Markdown artifact commands stay byte-compatible
- [ ] an executable census assigns every CLI Markdown-bearing output site rendered, raw-source or
      artifact behavior and drives at least one assertion for each assignment
- [ ] pager behavior is explicitly accepted or declined; if accepted it is TTY-only, honors
      `PAGER` plus a disable path, invokes directly without a shell, and cannot change raw,
      redirected, JSON or artifact bytes
- [ ] the CLI maps every exhaustive semantic role through its terminal theme, including monochrome
      and ASCII fallbacks, without exposing dependency-specific parser types
- [ ] auto/always/never color, redirected output, ASCII, narrow width and malicious content are
      tested
- [ ] help, changelog and upgrading docs explain the compatibility boundary
- [ ] the changed `show` behavior has a named `Behaviour` and a proof that fails if raw display
      returns
