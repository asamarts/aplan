## Why

`ci/validation.yml` gives the `plan-and-generated-contracts` class (`aplan/`, `ROADMAP.md`,
`ROADMAP.status.md`, `.aplan.yml`, `AGENTS.md`) and the `documentation-and-policy` class
(`README.md`, `CHANGELOG.md`, `docs/` and the other prose) only the `spec` gate. Several tests
in `crates/aplan/tests` read those files: `policy.rs`, `edge_kinds.rs`, `traces.rs` and
`blueprint_examples.rs` read this repository's `aplan/tasks/` and assert its shape, and
`greenfield.rs` runs the recipes in `docs/quickstart.md` and, since `A2-167`, `README.md`. A pull
request that changes only those files therefore merges without running the tests that would fail
on it. PR #38 did exactly that on 2026-11-18: it added the `M-` milestones and traced tasks,
passed its CI, and broke those tests on `main`, which surfaced only on the next code change.

## Acceptance criteria

- [ ] a change to a file that a test reads runs that test's gate, or a recorded decision names
      the files left out and why
- [ ] the selection's own tests cover a plan-only change and a README-only change
