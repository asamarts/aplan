## Why

Reported in #32 (item 1). `aplan start` accepts a task whose blockers are not done, exits 0
and says nothing; nothing later complains. A person may know better, so refusing is wrong,
but silence hides a likely mistake.

## Acceptance criteria

- [ ] `start` on a task with unfinished blockers stays exit 0 and prints `note: <ID> still waits on
      <blockers>`
- [ ] the note lists the same blockers `why` reports
- [ ] MCP `aplan_start` returns the same note in its result, since it starts tasks by its own path
- [ ] a comment on #32 records item 1 done, citing this task
