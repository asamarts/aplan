## Why

`export-agents-md` emits `##` headings. The block is placed by markers, so it can land anywhere in a
host document, and the tool cannot see what heading depth is in use around it.

In one adopting repository the block went under an existing host heading,
`## The one rule that matters: the plan is the source of truth`, and the first generated line was:

```markdown
## The plan is the source of truth
```

A duplicate title, one level too shallow, immediately under its own section heading. The generated
`## The loop`, `## What closes a task here` and `## Through MCP` then became siblings of the host
document's top-level sections rather than parts of the block.

The fix took a minute: rename the host heading and accept the block's sections as top-level. But it
is a hand-edit of the document around a region the tool owns, made to accommodate the tool, and it
has to be made again by every repository that places the block anywhere but the end of a file,
which the command's own help explicitly invites:

> To put the block somewhere other than the end of a file, write the two markers where you want it.

## Acceptance criteria

- [ ] the generated block's heading depth can be chosen, or is derived from the heading the markers
      sit under
- [ ] whichever it is, `--check` agrees with what `--write` produces at that depth, so the gate does
      not report drift against a document the tool itself shaped
- [ ] the default is unchanged for a block appended to the end of a file, which is the case that
      works today

## Notes

Found by an adopting repository using `export-agents-md` to replace a hand-written policy section.

Cosmetic, and recorded as such: it misshapes a document rather than misreporting a plan. It is here
because it is paid on first use of the feature, by the reader least able to tell whether the output
is wrong or their placement is.
