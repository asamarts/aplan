## Why

The release transaction proves one exact source, validates it, builds inside an immutable native
environment, and publishes a checksum. The checksum detects changed bytes only after a consumer
has obtained an authentic digest. Nothing a consumer can verify currently binds the archive digest
to the public repository, the protected release workflow, or the exact hosted build invocation.

GitHub artifact attestations can close that gap without storing a signing key. A short-lived OIDC
identity obtains a Sigstore certificate, and an in-toto statement binds the archive digest to the
workflow and source. The attestation must be part of the existing same-job transaction: after the
validated reproducible build, before any registry package or GitHub asset is published, and
verified before publication can proceed.

## Acceptance criteria

- [ ] an ADR states the subject, signer identity, verification policy, rerun semantics, and the
      boundary between build provenance, release approval, checksums, and reproducibility
- [ ] the protected release job uses the current GitHub-owned attestation action pinned to one
      reviewed full commit and grants only the OIDC and attestation permissions it requires
- [ ] the one release archive is attested after exact-source validation and construction, then
      verified against `asamarts/aplan` and `.github/workflows/release.yml` before any publication
- [ ] manual release staging exercises attestation and verification without publishing crates or
      release assets; a failed, skipped, or weakly scoped verification cannot reach publication
- [ ] executable tests audit the action pin, permissions, single-subject path, workflow ordering,
      tag-only publication boundary, exact verifier arguments, and zero/many archive neighbours
- [ ] consumer and maintainer documentation gives the exact online verification command without
      claiming that the previously published v0.5.2 archive has an attestation
- [ ] change-aware and complete validation pass, followed by a successful protected hosted staging
      run that creates and verifies an attestation from the integrated source
