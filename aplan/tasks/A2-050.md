## Why

Reported in #30. A trace anchor can match both a heading and a table row; the heading wins.
When that heading is renamed, the same anchor silently resolves to the row instead. `check`
passes and `verify` reports only an ordinary `APLAN045` section change, which a repository
may run as advisory. Deleting the row as well produces the `APLAN008` error a rename should
have produced, so the row hides the error.

Options from the report, in its order of preference: (1) record the element kind in the
stamp and say when an anchor now resolves to a different kind; (2) lint an anchor that
matches both a heading and a row when it is written; (3) document the precedence and the
consequence. Option 1 changes what a stamp records, so it needs a decision before code.

Untestable: a decision record.

## Acceptance criteria

- [ ] a decision is recorded (ADR or HLD section) choosing among the options, with the stamp format

- [ ] the implementation task's criteria are updated to the decision, or it is dropped with the reason
