## Why

The TUI consumes the same semantic Markdown document as the CLI but has a different delivery
problem: cells, scrolling, focus, reflow and incremental redraw. Keeping this adapter separate
prevents the CLI compatibility change (A2-115) from waiting on the TUI inspector and gives every
semantic role an independently executable sink audit. It extends the existing TUI task inspector.

## Acceptance criteria

- [ ] the task inspector maps the shared exhaustive block/span roles into Ratatui cells without
      reparsing Markdown, exposing parser-crate types or inventing a second theme vocabulary
- [ ] headings, lists, quotes, code, links, tables and fallbacks remain understandable in
      monochrome, ASCII, narrow and reduced-motion configurations
- [ ] resize reflows predictably, selection/back navigation survives harmless refreshes, and large
      bodies scroll without eager whole-document layout or full-screen redraw on every input
- [ ] link destinations and image/raw-HTML fallbacks remain inert text unless a separately
      admitted safe action handles them; task content cannot open files, spawn commands, fetch
      resources or inject terminal controls
- [ ] every semantic member drives a TUI disposition assertion, while cross-sink tests prove CLI
      and TUI consume the same semantic value even where their layout differs
- [ ] reducer, snapshot and PTY journeys cover malformed Markdown, Unicode graphemes, deep
      nesting, long tokens, wide tables, focus changes, scrolling and resize
- [ ] the executable TUI command/option census assigns the changed task-body treatment explicitly
      and contextual help explains how to obtain exact raw Markdown through the CLI
