## Why

One adopting repository's pre-push hook intermittently failed while printing 307 advisory
findings: `rendering report: Resource temporarily unavailable (os error 11)`. The same gate passed
on retry without a plan change. The inherited stdout descriptor was non-blocking, a partial report
filled the pipe, and `WouldBlock` escaped as an internal failure that the hook described as an
unclean plan.

Ignoring `WouldBlock` would silently truncate the report, while restarting the whole renderer
would duplicate the prefix already written. The retry must happen at the byte-write boundary and
must remain responsive if the downstream reader never drains.

## Acceptance criteria

- [x] a writer that returns `WouldBlock` after a partial write is retried without truncating or
      duplicating any byte
- [x] repeated `WouldBlock` has a bounded wait/cancellation policy and cannot busy-spin forever
- [x] `BrokenPipe` retains its deliberate success semantics, while unrelated I/O faults still
      surface as internal failures rather than plan findings
- [x] an end-to-end test drives a report larger than a pipe buffer through a non-blocking
      descriptor and compares the complete output byte for byte
- [x] the process verdict continues to come from validation, never from whether stdout happened
      to accept one write immediately
