## Why

An end-to-end comparison of v0.6.0 with `main`, a code review and a documentation audit of
`A2-169` on 2026-11-18 found that the tag rule in `aplan_core::yaml` mistook some untagged values
for tags, read the strict formats with the wrong grammar once a tag appeared, and was described
in places by claims the code does not bear out.

- **An enum took a key or a string for a tag.** `ayaml` hands an enum target a variant named by a
  tag, by a string, or by a mapping's key alike, and the rule treated any variant spelled
  `<...>` as a dropped global tag. So `status: {"<x>": done}` read as `done` and an `.aplan.yml`
  with `id_strategy: {"<x>": ulid}` loaded, where v0.6.0 and `ayaml` refuse both. A global tag
  over an enum also added a fake `<tag:yaml.org,2002:timestamp>` segment to an error's path, and
  an unknown variant named by a mapping's key was reported at the mapping, not at the key.
- **The strict formats changed grammar beside a tag.** A capture, blueprint or dependency
  manifest that carried a tag was read again by the compatibility reader, which parses `?x` in a
  flow sequence as a mapping and refuses a byte-order mark before `---` and an anchor with a colon
  in it. `ayaml` 0.1.3 does offer a seed on the strict reader, through its document cursor; the
  docs and ayaml issue 191 said it did not.
- **The unknown-key report invented an error.** It read `.aplan.yml` under the rule, wrote it back
  with the unknown keys removed and parsed the result, so a number beneath a verbatim tag came
  back as quoted text, and `effort_days_per_week: !<tag:example.com,2000:n> 7.5` beside an unknown
  key was reported as a type error the real load does not have.
- **Refusals said less than they could.** `deny_warnings: !!timestamp true` was refused as
  `invalid type: string "true", expected a boolean`, which hides the tag that made it text. A
  local tag was named in spellings YAML refuses: `a: ! 1` as `!<!>` and `!%3Cx%3E` as `!<!<x>>`.
- **The record overstated or missed readings.** Newly accepted: `!!int 017` (17), a bare
  `!!null`, `!!float "2.5"`, and `!custom ~` read as null where a field takes nothing. Newly
  refused: `phase: !!float 1` in a task, which v0.6.0 loaded as phase 1, and
  `deny_warnings: ! true`. Readings older than `A2-169` were missing too: the strict formats read
  a byte order mark before `---`, `[?x]` and an anchor name with a colon as YAML 1.2 defines them,
  where v0.6.0 refused or read otherwise, and `id_strategy: {ulid: ~}` loads, where the bridge took
  an enum only as a tag or a string. The reason given for the quoted-scalar divergence was wrong: the
  bridge's numeric reads took only plain scalars, whatever the field's type. Two tests passed
  without the rule at all, one comparison checked only that both reads succeeded, and the corpus
  differential read through `ayaml` directly instead of the product's reader.

## Acceptance criteria

- [x] an enum is asked of `ayaml` as any value, so only a tag is dropped as one: every untagged
      form of an enum, and every refusal of one, reads exactly as `ayaml` reads it, and a global
      tag over an enum adds nothing to an error's path
- [x] a strict-format document that carries a tag is read through the strict reader's cursor,
      and the three grammar cases above read as the strict reader reads them
- [x] the unknown-key scan keeps tags when it writes the document back, and reports nothing
      further for a file whose only fault is the unknown key
- [x] a typed scalar refused beneath `!!timestamp` or `!!binary` names the tag, and a local tag is
      named in a spelling that reads back as the same tag
- [x] the hostile-input differential reads the corpus and every input through `aplan_core::yaml`,
      pins each newly accepted and newly refused reading above with its reason, and every
      request beneath a local tag is compared with the bridge
- [x] the module docs, `docs/design/yaml-parser.md` and the CHANGELOG describe the measured
      behaviour, and ayaml issue 191 carries a correction of its wrong claims

## Decisions

- **Typed values read through a buffer keep the any-value rule.** `.aplan.yml`'s `test:` runners
  are buffered as a generic value before their shape is known, so a number beneath a global tag
  there is text, which the field refuses, as v0.6.0 did. Keeping the tag through the buffer would
  need a side channel past the rule for one rare spelling; the behaviour is recorded instead.
- **An error under a tag points at the value beneath it.** `ayaml` gives a tagged node the place
  of its value, and the rule cannot see the tag's own place, so the line is right and the column
  can be later than v0.6.0's. Recorded, and reported to `ayaml`.
- **An error inside a variant named by a string or a local tag no longer names the variant in its
  path.** Asked for any value, `ayaml` has no key to add, and nothing outside it can add one.
  A malformed variant is still refused with the same message and place.
