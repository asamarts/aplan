## Why

The observational latest-stable job reports that Rust 1.100.0 is available while the
repository pins 1.99.1, and asks for an explicit upgrade decision. Under 1.100 the build
fails `-D warnings` on one new clippy lint in `aplan-core` (an `if` guard that returns a bool
literal and is followed by another arm) and emits two Cargo manifest warnings:
`package.homepage` is redundant with `package.repository`, and the `trycmd` workspace
dependency is unused.

The maintainer decided (2026-11-17) to keep the pin at 1.99.1 for the v0.7.0 release, so the
release compiler stays the one already qualified for byte-reproducible artifacts, and to make
the source clean under both compilers now. Moving the pin is separate, later work.

The job had also failed on 2026-11-10 for a reason of its own, and did so again on 2026-11-18 once
the lint was fixed. Its workspace tests run validation profiles whose child processes resolve the
pinned compiler, which this job never installed, so their parallel rustup installs raced on one
download file and failed. The job now installs the pinned compiler once before its tests, and the
toolchain contract test requires that order.

## Acceptance criteria

- [x] clippy with `-D warnings` passes under the pinned 1.99.1 and under 1.100.0
- [x] Cargo emits no manifest warning under 1.100.0, and crates.io metadata still names the repository
- [x] the observational latest-stable job passes; the pin and `rust-toolchain.toml` are unchanged

## Why it is `untestable`

The lint and manifest fixes are proved by the compiler and clippy accepting the source under both
toolchains; while the pin stays at 1.99.1, no test fails if they are reverted. The one part a test
pins is the latest-stable job's install order, in
`toolchain_contract::msrv_latest_stable_and_release_keep_distinct_authorities`.
