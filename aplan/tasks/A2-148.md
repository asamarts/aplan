## Why

In an adopting repository, one eight-day task accumulated several reviewed delivery increments
while the plan still exposed one flat `in_progress` task. Progress moved into prose because aplan
has no subtask or decomposition relation. `contains` is milestone-only; `blocked_by` sequences work
but does not say which task integrates it, and counting effort on both a parent and children
double-counts the cut.

This work must not smuggle in a second grouping hierarchy (ADR-0014 models one grouping level, and
ADR-0030 keeps membership an edge). It should model bounded outcomes and an integration boundary
while preserving exactly one cut per task, one source of status truth and deterministic graph
semantics.

## Acceptance criteria

- [x] research and an ADR choose task-level containment, a new typed relation, or a precisely
      specified dependency convention; rejected alternatives cover grouping abuse, arbitrary DAG
      hyperedges, checklist parsing and status duplication
- [x] the model states whether the parent is work, an integration gate or a rollup, how status and
      readiness derive, and how effort is counted exactly once without zero-effort fiction
- [x] every work task still belongs to exactly one cut; missing, duplicate, cyclic, cross-cut and
      terminal-parent relations fail closed with diagnostics that name the offending subjects
- [x] `show`, `why`, `tree`, `ready`, graph, roadmap, summary, JSON, MCP and TUI expose the relation
      consistently, including current increment, remaining children and the integration boundary
- [x] import/export, add/move/drop/supersede/rekey and evidence mutations preserve or explicitly
      refuse the relation; existing plans require no migration until they opt in
- [x] executable fixtures cover flat, one-level and nested candidates, partial completion, a parent
      that owns integration effort, cut rollups and every refusal boundary, with CLI/MCP parity
- [x] schema, rule catalogue, agent contract, upgrade guide, HLD, changelog and facts make the new
      primitive programmable without requiring a consumer to parse task prose
