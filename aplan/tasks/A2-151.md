## Why

ADR-0031 deferred a second declared ordering signal until either dense plans remained flat after
the transitive-depth term or an adopter reported that `ready` offered the wrong work. An adopting
repository has now met that second condition: in a 65-task ready frontier with real dependencies,
two newly filed top-priority leaves ranked 61st and 65th even though the owner explicitly asked to
do them next.

The only persisted discretionary primitive is `prefer_after` (ADR-0025). Making six existing
top-priority tasks (ranked 4th to 50th) prefer the five new tasks honoured all 30 edges by moving
those six tasks later, behind roughly 55 unrelated tasks. It made the intended order worse. Moving
both leaves earlier with the current field would require every other offered task to name the later
one: 63 edges which go inert but remain stale opinions as soon as the promoted work finishes.

This evidence reopens the decision; it does not predetermine the replacement. The design must
compare a stable-topological interpretation which may move the preferred task earlier, an inverse
or non-pairwise persisted signal (including the previously dropped proposal for an ordered declared
family, such as a severity read only by `ready`), and an explicit invocation/session priority. It
must preserve the central boundary: a discretionary order changes only the offer, never readiness,
blocking, critical path or evidence.

## Acceptance criteria

- [ ] a new ADR evaluates the measured dense-frontier case against ADR-0025 and ADR-0031, compares
      the viable pairwise, non-pairwise and invocation-scoped shapes, chooses one bounded general
      primitive and marks only the superseded portions of the older decisions
- [ ] one command can promote one or several ready tasks without editing every unrelated ready
      task; its atomic add/remove lifecycle, persistence or deliberate ephemerality, expiry/stale-
      opinion behavior and deterministic conflict policy are explicit
- [ ] the chosen signal never changes readiness, `why`, `critical-path`, `APLAN007`, cut closure or
      evidence. Unknown, terminal, blocked, self, duplicate, mandatory-edge and cyclic/contradictory
      inputs have deliberate diagnostics rather than accidental no-ops
- [ ] `ready --explain`, human output and structured application projections name exactly which
      signal moved which task, in which direction and relative to what baseline; CLI, MCP and TUI
      can inspect and operate the same typed semantics without parsing rendered output
- [ ] schema/import/export/rekey and compatibility behavior are covered if plan syntax changes;
      older plans retain byte-for-byte order, and the behavior widening has a proved capability
      name and upgrade guidance
- [ ] tests reproduce the 65-task dense-plan failure with a generic fixture, force every other rank
      term and id order to disagree with the expected result, cover multiple promoted groups and
      removals, and retain deterministic/property and scale budgets
