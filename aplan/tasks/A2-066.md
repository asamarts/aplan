## Why

An adopting repository migrated a 277-task plan from a table that never recorded effort. Inventing
277 estimates to quiet `APLAN009` would be the unfalsifiable claim this tool refuses everywhere
else, so the plan takes the warnings deliberately.

```console
$ # with a placeholder `effort_days: 1.0` on every task
critical path: 66.0 days across 66 task(s)

$ # with no effort at all, which is the honest state
critical path: 0.0 days across 1 task(s)
```

Both numbers are useless, and not equally. The first is fabricated. The second discards
something real: **the longest chain of dependent tasks is a property of the graph, not of any
estimate.** Sixty-six tasks depend on one another in sequence there whether or not anyone has
sized them, and for a plan with no estimates that is arguably the most useful thing it can be
asked.

`roadmap` has the same shape, reporting `0.0d effort` rather than omitting a column it cannot
fill. A plan without estimates is the normal state of a migrated backlog.

## What to decide

- Whether the fallback is automatic (no task carries effort, so report chain length) or asked
  for, and how the output says which unit it is reporting, since a reader who sees `66` must
  not have to guess whether it is days or tasks.
- Whether `roadmap` follows, or whether its column is a separate decision.

## Acceptance criteria

- [ ] a plan where no task carries `effort_days` gets a critical path that names the longest
      chain, and says it is counting tasks rather than days
- [ ] a plan that does carry effort is unchanged, byte for byte
- [ ] the measurement is the fixture: 277 tasks, 0 with effort, longest chain 66
