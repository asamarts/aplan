## Why

Reported in #36, with a contributed fix in pull request #37. On a self-hosted runner the
install step needs tools that hosted runners provide, and the README does not list them, so a
new self-hosted setup gets a red job that looks like a failed plan gate.

The documented requirements must match what the install path actually runs: Linux x86_64, `bash`,
coreutils (`sha256sum`, `uname`, `mkdir`, `chmod`, `wc`, `basename`), `tar` with `gzip`, `awk`,
and a GitHub CLI new enough for the exact `gh attestation verify` flags the verifier passes
(`--signer-workflow`, `--source-ref`), which first shipped together in gh 2.68.0. `curl` is not
used by the install path. gh 2.102.0 or newer is the version to recommend: 2.97.0 and 2.102.0
fixed matcher weaknesses in exactly those flags, and 2.102.0 also fixed a symlink issue in
`gh release download`. Checking the version in the Action itself is `A2-162`.

Untestable: documentation only.

**Decision (maintainer, 2026-11-18).** The contributor of #37 gets until the other v0.7 members
are done to update it. After that the fix lands in a maintainer pull request that credits them
with a `Co-authored-by` trailer, and #37 is closed with thanks. #37 as written recommends gh
2.49.0, which lacks `--source-ref`, so it cannot be merged unchanged.

## Acceptance criteria

- [ ] the change credits #37's contributor as the decision above says, #37 is closed with thanks,
