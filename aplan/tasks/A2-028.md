## Why

Reported in #36, with a contributed fix in pull request #37. On a self-hosted runner the
install step needs tools that hosted runners provide, and the README does not list them, so a
new self-hosted setup gets a red job that looks like a failed plan gate.

The documented requirements must match what the install path actually runs: Linux x86_64,
`bash`, `tar`, `sha256sum`, `awk`, and a GitHub CLI new enough for the exact
`gh attestation verify` flags the verifier passes (`--signer-workflow`, `--source-ref`),
which first shipped together in gh 2.68.0. `curl` is not used by the install path. gh 2.102.0
or newer is the version to recommend: 2.97.0 and 2.102.0 fixed matcher weaknesses in exactly
those flags, and 2.102.0 also fixed a symlink issue in `gh release download`. Checking the
version in the Action itself is `A2-162`.

Untestable: documentation only.
