## Why

The `A2-009` parser switch refuses files v0.6.0 read. Probed on 2026-11-18 with the v0.6.0
release binary and a build of `main`:

| input | v0.6.0 | `main` |
|---|---|---|
| task `title: !!timestamp 2026-01-01` | reads the string | `APLAN001` "invalid type: enum" |
| task `title: !!binary aGVsbG8=` | reads the string | `APLAN001` |
| task `title: !<tag:example.com,2000:x> hello` | reads the string | `APLAN001` |
| task front matter opening with a `%TAG` directive and `--- # note` | reads | `APLAN001` |
| KEP `creation-date: !!timestamp 2024-01-15` | imports | refused: "untagged and internally tagged enums do not support enum input" |
| capture `title: !!timestamp 2024-01-15` | listed | `APLAN057` |
| task `title: !!str hello`, `effort_days: !!int 2`, verbatim core tags | reads | reads |

`ayaml` keeps a tag outside YAML's core schema on a generic value, where the bridge dropped it and
kept the scalar. Every product read that goes through a generic or JSON value then refuses it.
That is a regression for an adopter whose files use one, however rare, and the KEP message names
serde internals rather than the field. The hostile-input differential pins only the `%TAG` case.

## Acceptance criteria

- [ ] each row above reads in `main` as it does in v0.6.0, or a recorded decision says which
      stay refused, with an error that names the tag and the field rather than an enum
- [ ] the hostile-input differential pins `!!timestamp`, `!!binary`, a non-core verbatim tag
      and a directive inside front matter, each with its reason
- [ ] the CHANGELOG entry for `A2-009` and `docs/design/yaml-parser.md` describe the result
