## Why

The public repository already has no registered self-hosted runner, but every Linux workflow still
contains its obsolete private-repository selector and ordinary pull requests prove only Linux.
The former machine runner also remains as a running but unreachable container, while the private
`aplan.dev` repository retains a separate offline registration and schedules workflows that can no
longer start. This is neither one hosted design nor a valid fallback.

The release increment also needs a final independent audit after the first crates.io and GitHub
transactions. Release authority remains Linux-specific, but portable Rust and terminal behavior
must be proved on supported macOS and Windows hosts before a change can merge.

## Acceptance criteria

- [x] the release transaction, published v0.5.2 packages and assets, post-release reproducibility
      fix, protected environment, and rerun behavior are independently re-audited
- [ ] every public workflow uses an explicit standard GitHub-hosted runner and no source path can
      select persistent self-hosted compute
- [ ] pull requests and `main` require stable Linux, macOS, and Windows checks; macOS and Windows
      exercise portable compilation, unit behavior, and a real terminal without weakening Linux
      full-validation or release ownership
- [ ] scheduled compatibility runs retain moving runner labels and report every platform even when
      another platform fails
- [ ] executable repository tests census the complete workflow surface, runner labels, event
      coverage, hosted preparation, platform commands, and release isolation
- [ ] the public branch protection contract requires the three stable hosted checks
- [ ] the stale public-container credentials and private offline runner registration are retired,
      and `aplan.dev` no longer schedules work onto this machine
- [ ] change-aware and complete validation pass locally and the resulting hosted GitHub checks pass

## Operational boundary

Only the container named `aplan-runner`, its three `aplan-runner-*` volumes, its project-specific
user service, and repository runner registrations for `asamarts/aplan` or `asamarts/aplan.dev` are
in scope. No other project runner, container, service, or host setting may be changed.

## Release audit record

The annotated `v0.5.2` tag resolves to
`04b34a9be98b10e4ffbd1877632869b04eb527ad`. Hosted release run
<https://github.com/asamarts/aplan/actions/runs/41751133111> completed full validation, artifact
construction, crates.io OIDC authentication, all ten package publications and both GitHub assets
on that exact source. Every package is visible at 0.5.2, unyanked, checksum-matched to a fresh
registry download, and owned by `asamarts`.

The downloaded archive has SHA-256
`689d65309394a45e34f5e3b9cf7de3003534a357e534f78fffcfa8c88230cebe`, matching its sidecar and
GitHub's asset digest. It contains one static PIE executable that reports 0.5.2 and the expected
218 behaviours, 48 commands, 57 rules, 13 MCP tools, 9 formats and 5 evidence kinds. The protected
`release` environment requires independent review, prevents self-review, admits only `main` and
`v*`, contains no secrets, and no longer permits administrator bypass. The repository permits only
GitHub-owned actions and the pinned crates.io authentication action, with SHA pinning required.

PR <https://github.com/asamarts/aplan/pull/7> fixed the one post-release gap: the original release
builder did not own enough native inputs for a byte-reproducibility claim. Its independent clean
worktrees produced identical archive and binary hashes, its complete profile passed, and hosted
staging run <https://github.com/asamarts/aplan/actions/runs/41765230135> proved the corrected
builder without publishing. Published v0.5.2 bytes remain immutable; the corrected builder applies
to the next release. The publication scripts' rerun paths were re-audited: existing crates are
repackaged and checksum-compared, existing assets are downloaded and byte-compared, missing assets
may be filled, and divergent bytes are refused.
