## Why

An adopting repository pushed a two-commit increment whose tip passed every gate. The first commit
changed six traced sections without restamping their tasks and fails `check` with six `APLAN018`
findings when replayed alone; the second restamped them. Tip-only pre-push and CI gates therefore
accepted a history that gives a bisect, cherry-pick or incremental reviewer an invalid plan.

Rewriting published history is not the repair, and making every ordinary `check` walk Git would
turn a fast working-tree validator into an unbounded history operation. The missing surface is an
explicit, bounded range audit for an adopter whose integration contract requires every introduced
plan state to stand alone.

## Acceptance criteria

- [x] one explicit range mode validates the repository configuration, plan and declared documents
      at every commit introduced by a caller-supplied base and tip, in a deterministic documented
      order, without checking out over or otherwise mutating the working tree
- [x] the result identifies the commit and complete ordinary diagnostic for every invalid state;
      human and versioned machine output distinguish a green tip from an invalid intermediate
      commit and support fail-fast and complete-audit policies without changing default `check`
- [x] root commits, merges, empty ranges, equal endpoints, unrelated histories, missing objects,
      shallow clones and invalid revisions have explicit tested semantics and never collapse an
      incomplete audit into success
- [x] historical bytes are repository data only: validation executes no historical hooks,
      commands or evidence runners, follows no escaping links and does not populate or trust the
      current parsed-plan cache
- [x] work is bounded and avoids one repository traversal per task; commits whose relevant inputs
      are unchanged may reuse a proved-identical result while trace-bearing document edits remain
      relevant even when no task file changed
- [x] a fixture reproduces the two-commit sequence (red `APLAN018` commit, green restamp tip) plus
      a clean multi-commit range and proves ordinary tip-only `check` remains byte-for-byte stable
- [x] the widened meaning of the existing check surface has one proved behaviour name, release
      note, upgrade guidance and facts entry
