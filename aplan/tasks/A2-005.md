## Why

The post-publication download audit found that the v0.3.0 and v0.4.0 binaries retained the private
builder's home prefix in compiler source paths. The publication auditor scanned private repository
identities inside release payloads but did not apply the manifest's `forbidden_content` rules there,
so the earlier acceptance run passed for the wrong reason.

## Acceptance criteria

- [x] release compilation remaps the repository and builder-home prefixes before the first Cargo
      build and refuses an artifact that still contains either prefix
- [x] the publication auditor applies forbidden-content rules to release member names and payloads,
      including a match split across streaming chunks
- [x] replacement v0.3.0 and v0.4.0 assets are built from their exact public tag commits, checksum
      correctly, contain no registered private identity or forbidden prefix, and replace the
      affected public downloads
- [x] the complete public profile and hosted pull-request checks pass
