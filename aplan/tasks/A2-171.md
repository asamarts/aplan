## Why

A review of the `A2-018` fix on 2026-11-18 found the cost it removed was paid more often than it
needed to be. `rebuild_work_projection` calls `WorkCatalogue::project`, which builds a new `Graph`
over every task and ranks the ready work, on each key that moves the selection. `rebuild_task_browser`
ends by calling `rebuild_work_projection`, so the call sites that run both, such as selecting a
promoted task or the selection after a mutation, project twice per key. Neither the plan nor the
ready set changes when only the selection moves.

`A2-018` made each ranking linear, which is what passes the gates today; this is the next margin,
and the one `A2-164`'s budgets would otherwise absorb.

## Acceptance criteria

- [ ] a key that changes only the selection reuses the graph and ranking of the loaded snapshot
- [ ] no key projects the work twice
- [ ] the large-fixture interaction metrics in `tui_performance.rs` do not regress, and the
      selection's work projection is unchanged on every fixture
