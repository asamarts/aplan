## Why

Reported in #31; implements `ADR-0070` (`A2-052`). Today the last commit that touched any byte of
the task file (or any working-tree byte diff) is taken as the review point, so status, tag,
dependency, owner, and formatting changes clear `APLAN045`.

## Acceptance criteria

- [ ] `ADR-0070` substantive-baseline detection is implemented: `APLAN045` baselines against the
      most recent commit (or uncommitted working-tree change) that altered `title`, `body`,
      `paths`, or `traces`; non-substantive edits (`status`, `tags`, `owner`, `blocked_by`,
      `prefer_after`, `effort_days`, `phase`, `revisit_at`, `version_impact`, `ratified_by`,
      `contains`, or frontmatter formatting churn), whether committed or in the working tree, no
      longer clear `APLAN045`
- [ ] `aplan review <ID>` (and its MCP peer `aplan_review` in `crates/aplan/tests/mcp_parity.rs`)
      accepts live tasks with resolvable anchored traces, writes kind-tagged current
      `trace_fingerprints` (`ADR-0069`) through the guarded surgical writer without committing, and
      refuses terminal tasks or tasks without resolvable anchored traces
- [ ] `APLAN045` clears on a live task's `trace_fingerprints` entry only when the stored stamp
      actually matches the current traced section (a bogus hand edit does not clear it, and a later
      edit to the traced section re-fires `APLAN045`)
- [ ] the rule's fix text describes both legitimate remedies (updating the task's substantive
      content or running `aplan review <ID>`)
- [ ] the narrowed clearing condition for existing `APLAN045` has a `Behaviour` and executable proof
      in `crates/aplan-core/src/behaviour.rs`, and `docs/rule-catalogue.md`, `docs/upgrading.md`,
      `facts.json`, and `CHANGELOG.md` are updated
- [ ] #31 is closed
