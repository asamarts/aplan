## Why

An adopting repository called this "a precondition for the product's central claim that nothing in
the adoption path checks or mentions".

`test` is the strongest evidence kind and the one `evidence.require_min_strength` steers a
repository toward. A citation resolves only against a runner that can **list** names and **run** one
of them. A repository whose suite is a single all-or-nothing command (for example
`node verify.mjs`: 309 assertions, exit 0 or 1) has no name to cite, so it settles for `commit`
evidence throughout: the weakest kind, bound to a task only by path overlap, which `APLAN023` and
`APLAN024` exist to warn about.

**Nothing says so until it is too late.** The adopter discovers it at the moment they first try to
close a task honestly, having already been steered toward a policy their runner cannot satisfy.
`docs/upgrading.md` already guides a greenfield plan on which evidence policy to *start* at ("which
value is a stage, not a taste"); this is the precondition that decides whether the top of that arc
is reachable at all.

This is not a defect in the ladder. That adopter fixed it on its own side by writing a runner that
lists five names, and the fix is small once you know it is needed. Knowing it is needed is the gap.

## What to decide

**Whether this is documentation or a diagnostic.** `APLAN036` already reports a runner that lists
no tests, and `expect_tests: false` is how a repository says it meant that. Neither reaches a
repository that has not configured a runner at all, which is the population this is about.

**Where an adopter would actually meet it.** `docs/upgrading.md`'s applicability table answers "is
this feature for you", and `require_min_strength` has a row there already; the honest place may be
that row rather than a new document.

## Acceptance criteria

- [ ] an adopter deciding on an evidence policy is told, before they adopt it, that `test` evidence
      needs a runner that can list and select a name
- [ ] the guidance says what to do about it, since the remedy is small and specific
- [ ] the guidance works through the reported shape as an example: a repository whose only runner
      is one all-or-nothing command reads, before it chooses a `test` floor, that its `test`
      citations cannot resolve to single names
