## Why

In one adopting repository, the tasks that built its foundation models delivered arcs spanning
many commits. One commit is a weak proxy for an arc, a merge commit is deliberately diluted, and a
repository rename can leave the only commit touching the current path as a 675-file mechanical
change. There is no range evidence kind. A test citation is often the best current proof, but
`APLAN024`'s instruction does not explain that it can be recorded before a runner exists and
resolved later.

An earlier adopter judged retroactive evidence a product-boundary question; this one reproduced it
twice and explicitly asked for an upstream decision. The answer may remain the existing evidence
kinds plus clearer guidance, but it must say what claim each fallback actually proves.

## Acceptance criteria

- [ ] an ADR decides whether delivered arcs need a new range/history evidence form or are modeled
      with existing commit, test, file, URL and note citations
- [ ] the decision covers renamed paths, a multi-commit arc, merge dilution, repository locality
      and the cost/meaning of resolving history
- [ ] `APLAN024`'s instruction names the honest test-evidence route, including
      recorded-but-not-yet-resolvable tests, without implying an unchecked citation was executed;
      it does not present a prose body note as though that note could clear a deny-warnings gate
- [ ] any new evidence kind joins the exhaustive evidence-kind audit and has L1/L2/L3 semantics;
      if none is added, docs state why a commit range would not prove the task claim better
- [ ] fixtures distinguish a focused commit, a rename-obscured arc and a broad merge rather than
      testing only one candidate
