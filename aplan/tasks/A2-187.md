## Why

`A2-169` and `A2-179` worked around `ayaml` 0.1.3 keeping non-core global tags (`!!timestamp`,
`!!binary`, verbatim URI tags, and `%TAG` URI handles) and lacking a crate-root `from_str_seed`,
leaving three documented divergences from the `yaml_serde` bridge in `aplan_core::yaml`:

- beneath a non-core tag in YAML's namespace (`!!timestamp`, `!!binary`), typed numbers, booleans,
  and structs were still refused where the bridge parsed them;
- beneath any other global tag, `~` read as null for a unit target where the bridge refused it; and
- asking for an enum as any value via `EnumProbe` dropped the variant name from errors inside a
  variant named by a string or a local tag.

`ayaml` 0.2.2 (closing `asamarts/ayaml#191`) adds `compat::ParseOptions` with
`compat::GlobalTags::Drop`, `compat::from_str_seed_with`, crate-root `from_str_seed`, tag-naming
refusals, and the 0.2.x correctness and peak-heap improvements.

## Acceptance criteria

- [x] `ayaml` is pinned to `=0.2.2` in the workspace, `tools/tui-eval`, and
      `xtask/src/dependency_audit.rs`, with both lockfiles refreshed and the dependency audit green
- [x] `aplan_core::yaml::from_str` uses `ayaml`'s native `compat::GlobalTags::Drop` through
      `compat::from_str_seed_with`, eliminating all global-tag divergences from the bridge (every
      non-byte request across `!!timestamp`, verbatim, and `%TAG` global tags agrees with the
      bridge) and preserving variant names in enum error paths
- [x] `aplan_core::yaml::from_str_strict` uses `ayaml::from_str_seed` directly without a second
      parse, preserving strict grammar and refusals
- [x] `docs/design/yaml-parser.md` and `CHANGELOG.md` reflect `ayaml` 0.2.2 and the retired
      global-tag divergences, and `ci/scripts/preflight.sh --full` passes
