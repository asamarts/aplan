## Why

Found while auditing the change that made `verify --execute` distinguish a cited test that never
ran from one that passed (`APLAN037`), in that change's own diff.

Inserting a function between a doc comment and the item it documents leaves the comment
attached to whatever now follows. Rust accepts it silently: the comment is still a doc
comment, still on an item, just the wrong one. The result reads as one long doc comment whose
first paragraph describes something else, and the function that lost its documentation has
none.

That change did it once (`skipped_tests` landed between `runners_listing` and its comment) and
found more instances, all pre-existing:

| Where | The comment that was stranded | What it had been glued to |
|---|---|---|
| `crates/aplan-evidence/src/resolve.rs` | `runners_listing`'s "every runner is asked" paragraph | `near_match` |
| `crates/aplan-evidence/src/resolve.rs` | `report_empty_listings`' whole `APLAN036` comment | `judge_against_a_miss` |
| `crates/aplan-evidence/src/resolve.rs` | `covered_prefixes`' "what a runner claims" comment | `claims_locality` |
| `crates/aplan-e2e/tests/coverage.rs` | `list_runner`'s and `silent_runner`'s, in one stack | `filter_runner` |
| `crates/aplan-e2e/tests/coverage.rs` | `normalise`'s "strip the two things that differ" comment | `looks_like_a_sha` |
| `crates/aplan-config/src/lib.rs` | the greenfield-policy gate's own comment | `scaffold_examples` |

Those were fixed in that change, because they were in files it owned. **Eighteen more are left,
across seven files**: eight in `crates/aplan/src/lib.rs`, three in `crates/aplan-output/src/lib.rs`,
two each in `crates/aplan-core/src/close.rs` and `crates/aplan-interop/src/checklist.rs`, and one
each in `crates/aplan-core/src/anchor.rs`, `crates/aplan-core/src/save.rs` and
`crates/aplan/tests/consumer_facing.rs`.

This matters here more than it would elsewhere. A doc comment in this workspace is the argument for
the code, not a restatement of it: `define_rules!` generates a consumer surface from its comments,
`CLAUDE.md` sends a reader to "its doc comment on the `define_rules!` row" for why a rule exists,
and `xtask`'s gates read prose. A comment describing the wrong function is a wrong answer to the
question the file exists to answer.

## What has to be decided

**What the detector is.** The shape is mechanical: inside one `///` block, a line that ends a
sentence followed with no `///` separator by a line that opens a new summary ("A ...",
"The ...", "Whether ..."). Run over the workspace that finds twenty-two, of which the six
above were confirmed by reading. The false-positive question is the whole design question
(ordinary prose wraps a sentence boundary onto a new line constantly), and a gate that cries
wolf on a paragraph break is worse than no gate.

**Whether it is a gate or a one-off sweep.** The defect arrives through editing rather than
through writing, which is what argues for the gate: the sweep fixes today's eighteen and the
next insertion makes the nineteenth. Against it: `rustfmt` and `clippy` both see the shape and
say nothing, so this would be a house rule enforced by `ci/scripts/style.sh` or an `xtask`
invariant, and this repository already runs several.

## Acceptance criteria

- [ ] the eighteen remaining stranded comments are reattached to the items they describe, or
      the ones that are not really stranded are named with the reason
- [ ] a repository-wide pass reports none, and what it reports is checked by reading rather
      than by the count going to zero
- [ ] if it becomes a gate, it has a fixture that fires and one that stays silent over
      ordinary multi-paragraph prose
