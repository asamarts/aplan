## Why

An unscoped table, graph or machine collection can legitimately exceed the sub-100 ms bounded-read
response size. Buffering the complete rendering before the first write makes output volume look
like plan latency and can consume memory proportional to a 10,000-task response. Simply streaming
every serializer is not automatically safer: a late serialization error could leave a partial
machine document where the current buffered path emits none.

This task establishes the output boundary from measured terminal and pipe behavior, then streams
only formats whose post-validation rendering is infallible or can be preflighted. It preserves
stable bytes and explicit transport framing rather than weakening atomic-error semantics to win a
time-to-first-byte number.

The read path already removes deterministic waste, enforces its latency contract and reuses an
exact persistent plan snapshot across read commands (see `docs/design/read-path-performance.md`);
this task addresses the part of the cost those changes cannot reach, which is output volume.

## Acceptance criteria

- [ ] representative human, JSON and protocol responses establish a measured bounded-response
      threshold and separate plan/projection latency, time to first byte, transfer time, rendered
      bytes and peak buffering; the threshold is not an unexplained constant
- [ ] output above that bound begins within the read latency budget and uses bounded memory on the
      10,000-task corpus, while bounded responses still complete inside the budget
- [ ] streamed human and machine bytes remain deterministic and compatible with the buffered form;
      serializers are preflighted or remain buffered where a late error could otherwise publish a
      plausible partial document
- [ ] pipe closure, pager/terminal failure and interrupted protocol consumers stop production
      promptly with the established exit/framing semantics and without a panic or orphaned worker
- [ ] the derived read-surface inventory assigns every potentially unbounded output a buffered,
      streamed, paginated or explicitly capped disposition, and a new surface cannot omit one
