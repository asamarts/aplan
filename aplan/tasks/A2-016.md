## Why

The scheduled complete validation has failed every day since 2026-11-09 without a source
change, because new RustSec advisories now match the locked graph:

- `rmcp 3.4.1` is affected by RUSTSEC-2026-0457, RUSTSEC-2026-0461 and RUSTSEC-2026-0462
  (DNS-resolved SSRF in the OAuth client, an unbounded streamable-HTTP tool cache, and
  unbounded non-streaming HTTP response bodies). The fixes converge at `rmcp 3.9.0`.
- transitive `rustix 1.1.5` is affected by RUSTSEC-2026-0486 (undefined behaviour in safe
  code for zero-length xattr buffers), fixed in 1.1.6.
- `libz-sys 1.1.31`, reached through `git2` and `libgit2-sys`, bundles a zlib with a heap
  buffer overflow in `gz_vacate()` (RUSTSEC-2026-0544), fixed from `libz-sys 1.1.33`.
- `chrono` (RUSTSEC-2026-0543) and `humantime` (RUSTSEC-2026-0542) are now declared
  unmaintained, with no fixed release. `chrono` ships only because `rmcp` depends on it;
  `humantime` arrives only through the test-only `trycmd`, so it never ships.

The released v0.6.0 carries the vulnerable versions. aplan's MCP server uses only the stdio
transport, so the rmcp findings are probably not reachable, but a deny-by-default supply-chain
contract does not admit a known-vulnerable transport surface on that argument.

The maintainer decided (2026-11-17) to treat the two unmaintained advisories as reasoned,
revisitable exceptions rather than weaken the category: each gets an `ignore` entry in
`deny.toml` that says where the crate comes from, that no fixed version exists, and which
condition ends the exception.

## Acceptance criteria

- [ ] the direct `rmcp` requirement is at least 3.9.0 and the lock moves `rmcp`, `rustix` and `libz-
      sys` to fixed versions without unrelated dependency churn
- [ ] the complete MCP stdio tool surface and its typed refusals still pass; any SDK API change is
      handled explicitly rather than hidden behind a compatibility shim
- [ ] `deny.toml` ignores RUSTSEC-2026-0543 and RUSTSEC-2026-0542 only, each with a reason that names
      its path into the graph, the absence of a fix, and the revisit condition
- [ ] the committed dependency policy and validation selection agree with the new lock (`xtask`
      dependency audit passes)
- [ ] the supply-chain, MSRV, clippy, test and complete hosted validation gates pass from the same
      source revision, and the scheduled CI run is green again
