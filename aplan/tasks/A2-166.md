## Why

An audit of the `A2-009` cutover on 2026-11-18 found that it was not complete where no gate
looked, and that parts of its record overstated what was proved:

- **The TUI evaluator did not build.** `tools/tui-eval` is a separate workspace with its own lock.
  The cutover changed its code to call `ayaml`'s API but left its manifest naming `yaml_serde`
  under `yaml_compat`, so `cargo xtask tui-eval` failed to compile, and `--locked` refused the
  stale lock. No CI job builds it, so nothing noticed.
- **The KEP importer accepted an id the bridge refused.** `ayaml` keeps an integer wider than 64
  bits exactly, and `kep-number` is read as a generic value, so `kep-number:
  18446744073709551616` became `KEP-18446744073709551616` where the bridge refused the file.
- **Gate 4 was recorded as met.** The limit tests proved each ceiling against `yaml_compat` with
  explicit values, which proves `ayaml`'s mechanism; only some ceilings reach a product read in a
  test, the product depth test skipped the first refused level, and no test covered the `%TAG`
  expansion ceiling that 0.1.2 added.
- **The CHANGELOG and the design record said more than was true.** Duplicate keys in captures
  were already refused by their typed read, so the change is only an earlier, different message;
  emitted strings now use double quotes where the bridge used single ones; `add --from` manifests
  keep the compatible reader while blueprints use the strict one; tags other than a local `!tag`
  are now refused (`A2-169`); and two documents still described the bridge as current.

## Acceptance criteria

- [x] `tools/tui-eval` names `ayaml` `=0.1.3` as `yaml_compat`, its lock resolves no retired YAML
      package, and the dependency audit, which CI runs in its supply-chain gate, refuses a
      substituted or floating parser, a retired package, or a lock that no longer matches
- [x] the KEP importer refuses a `kep-number` wider than 64 bits, with a test
- [x] the product depth test checks the first refused level, and a limit test proves the
      tag-expansion boundary and its first refused neighbour
- [x] the CHANGELOG, `docs/design/yaml-parser.md` (gates 3, 4 and 5 and the tag divergence),
      `docs/design/tui.md` and `docs/upgrading.md` say what was proved and what was not, and name
      the tasks that own the rest (`A2-169`, `A2-173`)
