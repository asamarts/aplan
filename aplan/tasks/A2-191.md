## Why

A pre-release audit of `A2-190`, `A2-028` and the `v0.7.0` cut found three remaining gaps:

- **`CaptureActionOutcome::Predicted` (`--dry-run --format agent`) still told agents to reuse an
  uncreated task id.** `capture_action_agent_instruction` in `crates/aplan-output/src/lib.rs`
  handled `Refused`, but fell through for `Predicted` to the same instruction as `Applied`
  (`"Use the reported full capture id and task id for later machine requests"`), even though a dry
  run writes nothing to disk and may re-mint ids before apply.
- **`A2-020` declared an incomplete `paths` list for a real release cycle.** Comparing `v0.6.0`'s
  release and post-release commits (`2fe1aee`, `b7774c0`) shows release commits also update
  `docs/upgrading.md`, `AGENTS.md`, `facts.json`, `ci/validation-selection.json`,
  `.github/workflows/action-selftest.yml` and `tools/tui-eval/Cargo.lock`; omitting them would
  trigger `APLAN024` when closing `A2-020`.
- **`CHANGELOG.md` `[Unreleased]` omitted `A2-028` and the follow-up audit ids (`A2-189`,
  `A2-190`) and `#77`.**

## Acceptance criteria

- [x] `capture_action_agent_instruction` returns dry-run guidance stating nothing was written yet
      for `CaptureActionOutcome::Predicted` (both with and without `task_id`), pinned across all
      eight `(CaptureActionOutcome, bool)` cases in `aplan-output` and in
      `capture_inbox::capture_promotion_is_validated_atomic_and_idempotent`
- [x] `aplan/tasks/A2-020.md` declares every file the release and post-release commits touch and
      tracks closing `#77` upon `v0.7.0` publication
- [x] `CHANGELOG.md` `[Unreleased]` covers `A2-028`, cites `A2-189`, `A2-190` and `#77`, and uses
      consistent bullet spacing
