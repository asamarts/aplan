## Why

`close` resolves a cited test before it writes, and when the citation is not one the runner lists
it offers a near match, because the failure mode adopters hit first was a guessable wrong form
rather than a dead end. `near_match` in `crates/aplan-evidence/src/resolve.rs` tries three things in
order: the citation is qualified and the runner lists it bare, the runner qualifies and the
citation does not, and the two are one edit apart.

Each works. None composes. Measured against a runner listing
`imaging::bytes::tests::the_array_is_transposed_into_row_major`:

| citation | suggestion |
|---|---|
| qualified, one letter wrong | names the listed test |
| bare, spelled correctly | names the listed test |
| **bare and one letter wrong** | **nothing** |

The reason is in the third branch: `is_one_edit_apart` compares the citation against the *whole*
listed name, so a module prefix puts them dozens of edits apart before the typo is even considered.
An author who both drops the qualifier and mistypes gets the bare refusal, which is the dead end
the near match existed to remove.

**This is unobserved, and worth saying so.** One adopter hit the form mistake twice, in opposite
directions, and both are handled; that was confirmed by running the built binary both ways. Nobody
has yet hit the combination. It is filed because it is a one-line hole in a defence this project
already decided was worth building, not because an adopter is waiting on it.

## Acceptance criteria

- [ ] a citation that is both unqualified and one edit from a listed test gets the same suggestion
      either mistake alone would have got
- [ ] the three ways of matching are one decision rather than three sequential ones, so a fourth
      does not have to be composed by hand with the other three
- [ ] the table above is a test, each row of it
