## Why

Reusing a parser avoids owning Markdown, while reusing a complete terminal renderer may import a
second terminal stack, styling policy, image/network behavior or a large syntax bundle. Package
names and README claims are not enough to choose that boundary.

The workflow ergonomics design provisionally recommends a mature CommonMark parser
(`pulldown-cmark` with default features off) with aplan owning terminal rendering and layout in
`aplan-output`. This task measures that recommendation against the alternatives before any
renderer code makes it a de facto contract.

## Acceptance criteria

- [x] isolated prototypes compare `pulldown-cmark`, `termimad`, the `pulldown-cmark-mdcat`
      library (distinct from the `mdcat` application) and parser-only `comrak` against required
      constructs
- [x] resolved dependency count, duplicate terminal crates, MSRV, licenses, advisories and
      maintenance are recorded
- [x] clean build time, release binary delta, render throughput and peak memory are measured
      reproducibly
- [x] terminal and Ratatui integration fit, sanitization control and unsupported syntax are
      demonstrated
- [x] Unicode grapheme segmentation, display width and line-breaking dependencies are measured
      together; the design does not claim grapheme-safe wrapping from `unicode-width` alone
- [x] the result reuses the TUI's recorded minimal terminal dependency measurements when available
      and cannot introduce a second backend, event loop or theme authority by implication
- [x] syntect or a smaller highlighting option is measured separately from baseline code styling
- [x] an ADR records the versions measured, selects the dependency/features and compatibility
      policy without freezing a patch version as architecture, and explains each
      rejection/fallback
- [x] the proposal is corrected if measurement changes its provisional recommendation

## Why it is `untestable`

The task records comparative measurements and a dependency decision. Benchmarks and example
fixtures support the judgment, but no product test can prove which maintenance tradeoff to
choose.
