## Why

A program review in an adopting repository revised titles, effort, paths, traces and bodies on 67
existing tasks. The supported command surface can edit relationships, cut placement, tags,
lifecycle and evidence, but not those ordinary fields. Every change was therefore a direct file
rewrite that no mutation gate judged until a later `check`. This is not an exotic migration:
re-estimation and narrowing task ownership are normal results of reviewing a long-lived plan.

Atomic batch dependency rewrites remain the graph transaction they already are, and mixed lifecycle
transitions remain A2-132's. This task owns a source-preserving field editor for already existing
tasks, with both a small single-task form and one atomic manifest for a review spanning many tasks.
It builds on the typed, previewable change sets already exposed through the shared application
boundary and on the source-form-preserving list edits that dependency edits already use.

## Acceptance criteria

- [ ] a documented surface can set or deliberately clear title, owner, effort, paths, traces and
      body on an existing ordinary task; milestone-forbidden fields, status and evidence retain
      their existing dedicated lifecycle boundaries
- [ ] a batch can update many existing tasks against one identified plan snapshot, preview exact
      semantic and textual deltas, validate the complete post-state once and publish all files or
      none with compare-and-swap protection
- [ ] omitted, unchanged, set-empty and clear are distinct; blank values, duplicate operations,
      unknown ids, invalid anchors, forbidden milestone fields and stale snapshots refuse without
      changing any task
- [ ] unrelated YAML formatting, comments, scalar/list source form, frontmatter order and body bytes
      are preserved through the shared source-preserving primitives rather than serializing a task
      from scratch
- [ ] single and batch tests cover one and many values for every field, a trace fingerprint that
      must be restamped rather than silently retained, warning policy, write failure and concurrent
      modification
- [ ] CLI, application and MCP callers share one typed preview/publication outcome; HLD, README,
      changelog, upgrade guidance and facts expose the surface exactly once, using a command name or
      a proved behaviour according to whether the implementation adds or widens a surface
