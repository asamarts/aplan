## Why

Reported in #31. `APLAN045` says an open task's traced section changed; its fix text says
that editing the task records that somebody looked and clears it. Any commit touching the
task file counts, including a tag edit, `aplan start`, or a bulk edit across many tasks. A
plan's drift findings can therefore vanish as a side effect of routine work.

The report proposes clearing only on a change to the task's body, `paths` or `traces`, or on
an explicit review command (for example `aplan review <ID>`, the open-task counterpart of
`close --restamp`). Either changes what the rule promises, so it needs a decision first.

## Acceptance criteria

- [x] a decision is recorded defining which edits, or which explicit command, clear `APLAN045`
      (`ADR-0070`, `HLD.md`)
- [x] the implementation task's criteria are updated to the decision, or it is dropped with the reason
      (`A2-053`)

## Why it is `untestable`

This task records the design decision in `ADR-0070` and updates `HLD.md` and `A2-053`; no executable
product behaviour changes until `A2-053` implements it with regression tests.
