## Why

The field alone does not answer the everyday question ("what were the last N tasks we
completed?"). A typed application operation must own filtering, ordering and provenance so CLI,
MCP and TUI do not each reconstruct completion history. It goes through the existing shared
application boundary, the same concrete typed request/response layer the TUI and MCP server
already use.

The MCP adapter is separate in A2-119, allowing the engine and CLI to land without waiting on a
transport migration.

## Acceptance criteria

- [x] one concrete typed request/response through the shared application boundary carries input
      identity, basis revision, selector dimensions, history policy, deterministic page/limit and
      scoped completeness without exposing CLI argument or repository implementation types
- [x] `aplan completed` defaults to deterministic newest-first output and supports `--limit N`
- [x] time bounds plus cut, phase, owner and tag filters apply before limiting
- [x] milestones and dropped tasks stay out of the work view; zero/invalid limits and reversed or
      invalid bounds are refused clearly; exact boundary inclusivity follows the completion-time
      ADR from A2-108; unknown times never pass a time predicate
- [x] `--oldest`, `--history auto|never|required`, no-repository and incomplete-history behavior
      are explicit
- [x] the existing report-revision `--at` reads task data and derives history relative to that
      same basis rather than becoming a close-time flag or mixing historical and current inputs
- [x] human output shows absolute time, provenance, limitations and deterministic ties without
      presenting timestamp order as an exact causal sequence or relying on color
- [x] JSON has a stable typed shape with nullable instant, source, selected commit, input
      identity, basis revision, completeness/truncation reasons and applied request, and is color
      invariant
- [x] paging/limits remain snapshot-consistent: a changed input identity refuses continuation and
      no page duplicates or omits a row under equal or unknown timestamps
- [x] help, facts, README, HLD and changelog describe the shipped command and capability
