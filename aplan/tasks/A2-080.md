## Why

Reported by an adopting repository after it deferred a parked task by a month.

`revisit_at` works and needed no new concept: a task waiting on something outside the plan is
`blocked` with an empty `blocked_by`, moving the instant *is* the deferral, and `why` reports it
correctly and still refuses to call the wait over. The adopter recorded that as a success.

The gap is one level up. `check` and `verify` read no clock, by design and correctly (it is a
settled decision that reaching the instant never changes a status), which is why `due` exists
separately. But **`check` and `verify` are the two commands the generated agent contract names as
the gate**, so they are the two an adopter wires into CI, and `due` gets wired nowhere. Measured:

```console
$ aplan check  | grep -ci 'revisit\|due'   ->  0
$ aplan verify | grep -ci 'revisit\|due'   ->  0
```

That adopter now carries two parked tasks with a revisit, and both instants will pass in silence.
The field whose entire purpose is to stop an honest park from going quiet cannot do it.

**What makes this worth filing rather than a shrug is that the tool already solves this exact
shape, and solves it well.** `check` says:

```text
note: `check` is structural and did not open the repository, so 131 citation(s) on 77 task(s)
are unchecked rather than passing ... `aplan verify` is the half that resolves them; run it in
the same gate.
```

That is the pattern: here is what I did not examine, and here is the command that does. A parked
revisit is the same statement waiting to be made, and saying it costs no clock: counting how many
tasks *carry* the field is structural, while asking whether an instant has passed is not.

## What is already proposed, and what is left

The adopter's own proposal is a **note, not a warning**: it counts the field's presence and never
whether an instant has passed, so `check` stays clock-free and ADR-0024 is untouched, because
naming the command that resolves what you did not examine is not a recommendation. What is left to
decide is whether `verify` says it too (it reads a repository but still no clock), and whether a
plan carrying no parked revisit says nothing at all, which it should, or the note becomes noise
every adopter learns to skip.

## Acceptance criteria

- [ ] `check` reports how many tasks carry a revisit instant and names `due` as the command that
      resolves it, in the shape the unchecked-citations note already uses
- [ ] no clock is read: the count is of the field's presence, and a task whose instant has passed
      is indistinguishable from one whose has not, which keeps the decision that reaching an
      instant never changes a status intact
- [ ] a plan with no parked revisit says nothing
- [ ] whether `verify` carries the same note is decided and stated, not left to whichever
      renderer somebody edited
- [ ] the machine-readable surfaces carry the same answer, by the parity the format census
      already requires
- [ ] two runs at one commit produce identical output whatever the wall clock says, which is the
      determinism the adopter's own report asked for and the only way to prove no clock was read
