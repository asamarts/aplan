## Why

`A2-164` measured the TUI's three wall-clock gates five times on the reference host, each run in a
queue slot of its own and pinned to one CPU. Of 74 wall-clock metrics, 68 agreed across the runs
within the spread agreed in advance: 5% of the smallest p95, or 0.1 ms for a metric under 2 ms.
Six did not:

| metric | p95 of the five runs (ms) | spread |
|---|---|---:|
| `graph_focus_sparse` | 19.10, 17.51, 17.83, 17.31, 17.19 | 11.1% |
| `graph_focus_fan_in` | 1.74, 1.83, 1.62, 1.83, 1.79 | 0.22 ms |
| `graph_focus_crossing` | 4.28, 4.01, 3.92, 4.04, 3.93 | 9.2% |
| `pty_repository_cold_feedback` | 6.89, 7.20, 7.20, 7.20, 7.26 | 5.4% |
| `pty_repository_warm_feedback` | 7.13, 7.23, 7.25, 7.23, 6.84 | 5.9% |
| `pty_large_cold_feedback` | 7.31, 7.28, 7.35, 6.90, 7.24 | 6.4% |

The maintainer decided on 2026-11-19 that the reference host holds them to the hosted rule, 1.5
times their hosted budget, until they can be measured there. A reference run then failed a
passing revision on `pty_small_cold_feedback`, which had agreed: it read 9.70 ms against a 9.17 ms
budget, where it had measured 7.20 to 7.34 ms. So the same day every real-terminal first feedback
joined the hosted rule, nine metrics in all.

The hosted rule is loose for them: 75 ms for `graph_focus_sparse`, which measures 17-19 ms, and
375 ms for a first feedback of about 7 ms. A regression several times over would pass.

The two kinds differ:
- **Graph focus.** Within one run its p50 and p95 agree to 1%, so the variation is between
  processes. That points at something fixed per process, such as a hash seed or memory layout,
  and more samples in one process cannot narrow it.
- **First feedback.** It is the slowest of three process launches, and one launch in a run is often
  0.3 to 0.4 ms faster than the rest, or, once in the ten runs so far, 2.4 ms slower.

## Acceptance criteria

- [ ] the cause of each kind of variation is identified and recorded, with the measurement that
      shows it
- [ ] each of the nine is measured so that five reference runs agree within the agreed spread and
      a passing revision does not fail a reference run, for example over several processes for
      graph focus or more launches for first feedback, without lengthening the hosted gate by more
      than a minute
- [ ] each gets a reference budget by the rule of ADR-0067; `HOSTED_RULE_ON_REFERENCE` and the
      script's `HOSTED_RULE_BY_DECISION` are empty, or name only metrics whose measurement is shown
      to be inherently unstable, with their reasons
