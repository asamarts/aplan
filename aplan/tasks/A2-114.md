## Why

CLI and TUI need one interpretation of task Markdown. The reusable layer must land before the TUI
adapter without depending on a TUI crate. Rendering parser events directly to escape sequences
would also make reuse, width and hostile input hard to audit.

## Acceptance criteria

- [ ] an owned parser-backed semantic document covers headings, emphasis, code, lists, quotes,
      links, tables and breaks without exposing parser-crate types in its public API
- [ ] an exhaustive semantic-role/member table drives at least one assertion per member and makes
      a missing future sink disposition fail rather than silently drop content
- [ ] caller-provided render capabilities cover width, ASCII fallback, color, links and role-based
      themes without arbitrary markup execution or runtime renderer plugins
- [ ] the terminal sink is I/O-free and leaves a stable cell/span adapter boundary for A2-115
- [ ] headings, fenced-language labels, nesting and wide/narrow table fallbacks are readable
      without color
- [ ] Unicode display width, wrapping, long tokens and deep nesting are bounded and deterministic
- [ ] wrapping operates on validated grapheme boundaries and tests combining marks, emoji ZWJ
      sequences, variation selectors, ambiguous-width text and terminals with the selected width
      policy
- [ ] task text, URLs and raw HTML cannot inject CSI/OSC controls, fetch resources or execute
      anything
- [ ] images degrade to text; unsupported constructs preserve visible content rather than
      vanishing
- [ ] optional token highlighting ships only if A2-113 admitted it and always has an
      unknown-language/plain fallback
- [ ] golden, property and adversarial tests cover every semantic member and prove parser events,
      semantic values and terminal output agree
