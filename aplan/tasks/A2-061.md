## Why

This is the removal half of a deprecation runway that has already been announced. `tree` should
show only what can still block, and `--all` should restore the satisfied ancestry it shows today.

The `--live` filter was built first and left the default alone, because changing what an existing
command prints is what the runway exists for. The announcement shipped next: `tree --help` and
`--live`'s own help now say that a later cut makes live-only the default, with `--all` for today's
view. This task does it, a cut later, which is the shape this tool's deprecation-runway support
(a checkable planned removal and a generated report) gives its own deprecations.

## What has to be true first

The announcement has been in a released cut, so a reader of `tree --help` met the warning before
the behaviour moved under them.

## Acceptance criteria

- [ ] `tree` defaults to live-only, and `--all` prints what the default prints today
- [ ] `--live` keeps working, as a no-op that names itself, or is removed with its own note
- [ ] the count of what was withheld is printed under either default, so neither view is silent
- [ ] the corpus pins both, so the change is a reviewable diff rather than something a reader finds
