## Why

Completion history is a collection read, not an action. Keeping its MCP adapter out of the engine
and CLI task (A2-111) lets those consumers proceed without waiting on the transport migration
(A2-118), while this task can prove the resource-specific URI, paging, cache and protocol-version
contracts against the shared typed response.

## Acceptance criteria

- [x] a bounded resource template projects the exact A2-111 request and response without a
      transport-specific completion model or an `aplan_completed` rollup tool
- [x] its URI represents filters, order, history policy, limit and opaque continuation
      canonically, with documented maximum lengths and no source-controlled path interpretation
- [x] collection-page continuations are bound to the request and input identity; stale,
      malformed, oversized or tampered values are refused and cannot broaden the requested
      selection
- [x] resource content carries contract version, input identity, provenance, basis revision,
      completeness and deterministic ordering in a machine-readable media type
- [x] domain collection paging is distinguished from MCP's resource-catalogue pagination, and
      current-protocol cache hints prevent a changing working-tree answer from being shared or
      treated as fresh
- [x] current and supported legacy protocol clients receive equivalent subject data under A2-118's
      compatibility rules without parsing human prose
- [x] the executable MCP surface audit drives the resource/template disposition and proves that
      the CLI, resource and application response agree on every row and truncation reason
- [x] end-to-end tests cover empty, recorded, inferred, unknown, shallow, capped, stale-page and
      hostile-URI cases, including a lost response followed by a safe repeat read
