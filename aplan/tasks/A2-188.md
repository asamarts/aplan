## Why

Reported in #61. `crates/aplan-attest/build.rs` captured `env!("CARGO_MANIFEST_DIR")` at
build-script compile time rather than reading `CARGO_MANIFEST_DIR` at runtime, and did not emit
`cargo:rerun-if-env-changed=CARGO_MANIFEST_DIR`.

When a checkout or `target/` directory is moved or reused across paths, Cargo invokes the cached
`build-script-build` binary with the old checkout path baked in. Once the old path no longer
exists, `script_watch_paths`, `git_watch_paths`, and `git_head` all fail quietly, emitting only
`cargo:rerun-if-env-changed=APLAN_SOURCE_REV` and an empty `APLAN_SOURCE_REV=`. With no
`rerun-if-changed` paths emitted, Cargo caches the empty revision permanently across subsequent
commits and branch switches, so `aplan facts --identity` omits `source` until `cargo clean`.

## Acceptance criteria

- [ ] `crates/aplan-attest/build.rs` reads `CARGO_MANIFEST_DIR` at runtime and emits
      `cargo:rerun-if-env-changed=CARGO_MANIFEST_DIR`
- [ ] moving a Git checkout to a new directory while reusing its `target/` directory retains a
      non-empty `APLAN_SOURCE_REV`, stays fresh on unchanged rebuilds, and refreshes on subsequent
      commits
- [ ] named behaviour `facts.source_identity_survives_relocated_checkout` and an end-to-end
      regression test in `crates/aplan/tests/build_identity.rs` cover the relocated-checkout flow
- [ ] #61 is closed
