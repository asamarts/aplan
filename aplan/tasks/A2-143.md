## Why

An agent in an adopting repository closed a task and tried the natural `aplan next --format json`
spelling for "what should start next?" Clap rejected it safely but suggested `export`, the nearest
command name by spelling. The intended command was `ready`, which top-level help and the generated
agent contract already describe as the answer to that question.

The same repository later tried `aplan edit --help` while appending external decisions to a live
task. That command is intentionally absent: it was decided that task bodies remain author-owned
prose (a body-editing command was declined, not deferred), and `amend` repairs only closed-task
evidence. Clap nevertheless suggested `export`, which neither edits the task nor explains the
direct-file boundary.

Lexical correction is useful for genuine typos and should remain generic. It cannot recover a
small number of predictable semantic aliases whose spelling is unrelated to the command a user
needs. Add a deliberately bounded recovery layer at the same refusal surface instead of accepting
`next` as a silent alias: one canonical command should remain in scripts, help and facts, while the
mistake names an executable correction.

## Acceptance criteria

- [ ] `aplan next` remains a no-mutation refusal but names `aplan ready` as the executable recovery,
      including when trailing valid `ready` flags such as `--format json` were supplied
- [ ] `aplan edit` remains a no-mutation refusal, does not advertise `export`, and explains that
      task bodies are edited directly while `amend` is limited to closed-task evidence repair
- [ ] known semantic recoveries take precedence over a misleading edit-distance suggestion, while
      unknown misspellings retain Clap's ordinary lexical suggestion and exit behavior
- [ ] the recovery table is explicit, small and covered so it cannot become an undocumented alias
      vocabulary or silently diverge from real command names
- [ ] command-driven tests prove stderr, exit code, color/no-color behavior and an unchanged plan
      for both the semantic case and an ordinary typo
- [ ] top-level help or README makes `ready` discoverable as the "what next" operation without
      advertising `next` as a supported command
