## Why

One adopting repository needed to validate hand-authored `paths` before committing them and wrote
a third matcher in Python. It treated a bare directory as a prefix, while aplan's `globset`
configuration treats it as one literal filename. The local gate therefore accepted 23 entries
aplan matched against nothing, including every entry on one task.

The semantics are documented, but no supported command answers the operational question: which
tracked files does this exact entry match under aplan's matcher? A consumer must copy
`literal_separator`, `**`, `*` and `?` semantics into another language or infer them by provoking
`verify`. The field binds evidence to work, so competing readers are an integrity risk rather than
an ordinary convenience gap.

The same adopter supplied the semantic neighbour. A live task's globs all compiled and matched
tracked files, but they named a language binding's implementation while its work lived under the
platform SDKs. No matcher can infer that prose-to-tree mistake. This surface should make the exact
current match reviewable and compose with the history activity `A2-125` measures; it must not
label a nonempty match as relevant work.

## Acceptance criteria

- [x] one documented CLI surface accepts a task id or path glob and reports the exact tracked
      files matched by the same compiled matcher evidence verification uses
- [x] human and machine-readable output distinguish an invalid glob, a valid empty match and a
      non-empty match without callers parsing prose
- [x] bare directories, `/**`, `/**/`, `*`, `?`, dot-prefixed paths and separator boundaries are
      exercised against the evidence matcher's tests rather than a second implementation
- [x] output order is deterministic and a large match set has an explicit bounded or streaming
      contract
- [x] the adoption documentation points custom gates at this surface instead of teaching them to
      reimplement glob semantics
- [x] documentation gives the live-task preflight explicitly: inspect exact current matches here
      and bounded history through `aplan paths`, while stating that neither proves semantic
      relevance
