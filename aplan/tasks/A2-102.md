## Why

One adopting repository created a migration cut whose exit criterion promised that no `.mjs` files
would remain. Its twelve members' `paths` claimed 16 of 42 matching files, leaving 26 unowned while
every plan gate was green. A universal ownership rule would be wrong for most repositories; the
useful question is explicitly scoped: for this cut and this requested glob, which tracked files are
in no member's declared paths?

This is a report, not a warning. It puts two already machine-readable inputs together without
pretending prose exit criteria can be inferred.

## Acceptance criteria

- [ ] a report accepts one cut and one or more repository globs, then partitions matching tracked
      files into covered and uncovered by the union of that cut's non-milestone member paths
- [ ] invalid globs, an unknown cut, no matching files, overlapping ownership and a member with no
      paths have explicit machine-readable outcomes
- [ ] it uses the evidence matcher's semantics and historical tasks are included or excluded by a
      stated option rather than accident
- [ ] output order and counts are deterministic, with human and JSON forms suitable for a
      milestone exit gate
- [ ] a fixture reproduces the 42/16/26 shape with overlapping patterns so line coverage cannot
      substitute for the partition assertions
