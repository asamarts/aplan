## Why

The public dependency re-audit confirmed that the current YAML bridge is maintained and free of a
known advisory, but its parser remains C source translated to unsafe Rust. The private-era
qualification of the intended safe Rust backend found real compatibility and licensing blockers,
so that unfinished hardening work needs a public owner and a new qualification against an
immutable, licensed release.

## External prerequisites

The candidate backend must publish an immutable source revision with an explicit license grant,
Rust 1.88 support, and the compatibility fixes recorded in `docs/design/yaml-parser.md`. A moving
branch, sibling checkout, or unlicensed private source is not an admissible product dependency.

## Acceptance criteria

- [ ] an immutable licensed backend passes the complete value, mapping, tag, scalar, location,
      duplicate-key, serialization, and empty-document compatibility contract
- [ ] repository fixtures and hostile-input boundaries pass typed and generic differential tests
      without weakening existing assertions
- [ ] normal product graphs contain neither `yaml_serde` nor `libyaml-rs`, and license, source,
      advisory, duplicate, MSRV, schema, and release gates pass
- [ ] default and headless binary size plus parser-heavy latency remain within their committed
      budgets
- [ ] the complete local and hosted validation profiles pass from the same public source revision
