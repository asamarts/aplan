## Why

Completion history is a daily plan view, not a CLI-only artifact. The TUI should answer recent
work without hiding source quality or consuming overview space on narrow terminals. It builds on
the TUI's existing plan overview, task browser and task inspector, and on the typed completion
history operation from A2-111.

## Acceptance criteria

- [ ] a completion-history destination uses the shared typed operation and preserves
      deterministic order
- [ ] recent completions appear on the overview only where responsive layout has useful room
- [ ] filters, limits, recorded/inferred/unknown source and incomplete history are inspectable
- [ ] task selection opens the inspector and back navigation preserves the history request
- [ ] a changed input identity invalidates a continuation visibly rather than duplicating or
      omitting rows
- [ ] absolute time is available even if relative age is shown, and color is not the only source
      cue
- [ ] equal timestamps and unknown times have a stable visible disposition without implying that
      the interface knows an exact causal completion sequence
- [ ] reducer, snapshot and PTY journeys cover empty, legacy, shallow, narrow and large histories
- [ ] the executable TUI command/option census gives `completed` a native disposition
