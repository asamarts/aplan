## Why

Existing plans have done tasks but no recorded close time. A useful report needs a best-effort
bridge, while calling a commit timestamp the completion time would hide shallow history, imports
and delayed commits.

A2-109 records the exact close instant on every future close; this task covers the done tasks that
predate it. The inference follows the completion-time and historical-provenance semantics decided
in A2-108, and its result is always labelled as an observation of history, never as the recorded
fact.

## Acceptance criteria

- [x] one bounded history walk finds transition candidates for all requested tasks without a
      task-count-times-history algorithm
- [x] results carry `history_first_seen` provenance and are never persisted as `closed_at`
- [x] recorded values win, unresolved legacy tasks remain `unknown`, and no-Git operation stays
      useful
- [x] every result names the basis revision; complete means only complete for history reachable
      from that basis, while shallow, capped, rewritten/unobservable and unavailable limitations
      remain distinct
- [x] the selected result carries its commit id; renames, rekeys, merges, reverts, repeated done
      transitions, skewed/equal times, incomparable candidates, untracked files and deleted paths
      follow the completion-time ADR from A2-108 deterministically
- [x] automatic, forbidden and required history policies have distinct typed outcomes
- [x] work, latency, memory and output limits prevent unbounded traversal or buffering, and early
      stopping occurs only when the requested filters/order/limit remain provably complete
- [x] historical parsing is repository-data-only: it executes no historical/current config,
      follows no escaping worktree links and reports unsupported old task shapes as incompleteness
      rather than silently omitting them
- [x] fixture repositories prove the inferred subject, commit, timestamp and completeness,
      including multiple candidates where the offending/selected candidate is not first
