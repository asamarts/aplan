## Why

An adopting repository moved a task's design claim into the opening paragraphs of a chapter. The
chapter heading is the only anchor for those paragraphs, but its fingerprint recursively includes
ten subsections. Tracing it makes every unrelated subsection edit re-flag the task; narrowing to a
subsection leaves the opening claim untraced. The adopter exercised both failures on the same task
in two review passes.

Generic reproducer: `DESIGN.md` has `## Storage` with two opening paragraphs, then `### Layout` and
`### Compaction`. A task tracing `DESIGN.md#storage` is re-flagged by an edit to `### Compaction`
alone; a task tracing `DESIGN.md#layout` is not re-flagged when the opening paragraphs change.

This is distinct from list-item identity. An earlier decision measured arbitrary bullets as anchors
and deliberately declined to infer a name for them (a heading and a table row resolve, a list item
does not; ADR-0015 covers the table row). A heading already has a stable name and a syntactic body
range; the missing choice is whether a trace may select that body without descendant sections
while the current recursive meaning remains the compatibility default.

## Acceptance criteria

- [ ] the trace grammar can explicitly select a heading's own body through the next heading, while
      the existing heading form continues to include descendants byte-for-byte
- [ ] changing the selected opening paragraphs re-flags the task, while changing only a child
      subsection does not; insertion, deletion and reordering of children have the same result
- [ ] empty heading bodies, fenced pseudo-headings, duplicate slugs, table rows and nested heading
      levels have deterministic tested semantics and actionable unmatched-selector diagnostics
- [ ] `check`, `close`, `close --restamp`, CLI, application and MCP resolution share one anchor
      implementation and preserve atomic refusal behavior
- [ ] documentation distinguishes recursive heading, heading-body and table-row units and retains
      the existing explicit boundary: arbitrary list items do not gain inferred anchors
- [ ] this widening of existing trace behavior has one proved capability name, release note,
      upgrade guidance and facts entry
