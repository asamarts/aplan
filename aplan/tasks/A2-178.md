## Why

On 2026-11-18 the coverage gate failed
`progress::command_lifetime_progress_respects_grace_or_reports_a_real_slow_run` at a host load of
about 4: `aplan --progress always check` printed `progress: command: complete` and no line
before it. The test accepts a run that prints no progress at all, and refuses one that prints its
end without ever having shown it was active.

The command's progress renderer in `crates/aplan/src/lib.rs` explains it. When the grace period
ends while output is paused, `ProgressGate::due` returns `Reveal` and records a draw, but
`draw_active` only marks the row `Suppressed`. On `Resume` the row is redrawn only when the
output is animated, so with static output (stderr not a terminal, as under `--progress always`
in CI or a captured log) the active line is never written. When the command ends, the gate
believes the row was shown and `finish` writes the terminal line, so a reader sees a run end
that never visibly started. Coverage instrumentation slows the run enough for the grace deadline
to land inside a pause.

## Acceptance criteria

- [ ] a static progress row that a pause held back is written when output resumes, or the
      terminal line is withheld when no row was ever written, and the choice is stated here
- [ ] a deterministic renderer test drives a reveal during a pause, a resume and the command's
      end, and asserts the lines written for both animated and static output
- [ ] the process-level test above passes in a coverage run, which instruments the binary
