## Why

On 2026-11-18 the coverage gate failed
`progress::command_lifetime_progress_respects_grace_or_reports_a_real_slow_run` at a host load of
about 4: `aplan --progress always check` printed `progress: command: complete` and no line
before it. The test accepts a run that prints no progress at all, and refuses one that prints its
end without ever having shown it was active.

The command's progress renderer in `crates/aplan/src/lib.rs` explains it. When the grace period
ends while output is paused, `ProgressGate::due` (`crates/aplan-output/src/progress.rs`) returns
`Reveal` and records a draw, but `draw_active` only marks the row `Suppressed`. On `Resume` the
row is redrawn only when the output is animated, so with static output (stderr not a terminal, as
under `--progress always` in CI or a captured log) the active line waits for the next progress
event. When the command ends before one arrives, as it does right after the final report's print
pause, the gate believes the row was shown and `finish` writes the terminal line, so a reader sees
a run end that never visibly started. An interrupt takes the same path through `Stop`, which
prints `progress: command: interrupted` for a row that was never written. Coverage
instrumentation slows the run enough for the grace deadline to land inside a pause.

## Acceptance criteria

- [x] a static progress row that a pause held back is written when output resumes, or the
      terminal line is withheld when no row was ever written, and the choice is stated here
- [x] the same holds for the interrupted line that `Stop` writes
- [x] a deterministic renderer test drives a reveal during a pause, a resume, and then the
      command's end or an interrupt, and asserts the lines written for both animated and static
      output, through a write seam rather than stderr
- [x] the process-level test above still refuses an end without a start, and passes in a coverage
      run, which instruments the binary

## Decision

Draw any held-back row when output resumes (`pause_depth == 0 && row == Suppressed`) for both
static and animated output, and track `ever_painted` so both `finish` and `Stop` also withhold
their static terminal/interrupted line if the command terminates while still paused before any
active row was ever written. That preserves visible progress for genuinely slow static runs while
guaranteeing an end or interrupt line can never be emitted without a preceding active line.
