## Why

Reported in #58. When a task owns a shared decision or resource (such as a size/performance budget
ceiling or a shared gate file), other tasks whose `paths` touch that file have no way to discover
the owning task through `aplan show` or `aplan why` unless an explicit `blocked_by` edge was
already wired by hand. Even `paths` overlap between tasks misses the case where the decision task
owns design documents rather than the source file enforcing the ceiling.

## Acceptance criteria

- [ ] record the design decision for representing shared-path ownership in the plan or
      configuration (staying deterministic and pure over declared globs and graph reachability)
- [ ] surface the owning task in `aplan show` and `aplan why` (and optionally a check when an
      open task's `paths` overlap an owned path without depending on its open owner)
- [ ] regenerate derived schemas and `facts.json` if config or rules change
- [ ] tests cover matching overlap, non-overlapping paths, closed owners, and wired blockers
- [ ] #58 is closed
