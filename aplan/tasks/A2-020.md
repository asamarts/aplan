## Why

v0.7.0 carries the dependency security fixes, the safe YAML parser, CI health restored on
the current hosted images and the first fixes for findings that let a gate report less than
it should. The maintainer chose (2026-11-17) to ship the security fixes in v0.7.0 together
with that work rather than as a separate v0.6.1 patch.

The release automation already proves one exact source, builds reproducible archives,
attests provenance and publishes crates in dependency order; this task runs it and records
the result. Publishing is irreversible, so it starts only with the maintainer's explicit
go-ahead.

## Acceptance criteria

- [ ] every other member of the v0.7 cut is done
- [ ] the version bump, changelog and release run follow the existing release process from one
      validated source revision, with provenance verified before publication
- [ ] the TUI's reference gate (`ci/scripts/reference-tui-perf.sh`, ADR-0067) passes on that
      revision, and this task records the run: its commit, its loads and any metric within 5% of
      its budget
- [ ] the published GitHub release, crates.io packages and the Action resolve to v0.7.0, and the
      Action self-test passes against it
- [ ] the post-release commit returns `main` to a `-dev` version
