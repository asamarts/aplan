## Why

An adversarial post-merge audit of PRs #96 and #98 (`9098490..2cdc45e`, delivering `A2-085`,
`A2-051`, and `A2-053`) found four real edge-case and test-coverage gaps:

1. **YAML frontmatter / nested metadata pipe lines minted table-row anchors (`A2-085`):**
   `headings()` skipped leading YAML frontmatter and nested `---`-fenced metadata blocks, but
   `table_rows()` only skipped code fences, so a pipe-delimited value inside YAML metadata still
   minted a phantom table-row anchor.
2. **Uncommitted body/title/paths edit silently suppressed `APLAN060` on open tasks (`A2-051` /
   `A2-053`):** `check_live_task_trace` returned `None` on any `uncommitted_substantive` edit
   before checking `a.kind != b.kind`, so editing a live task's body hid a `heading <-> row`
   retargeting instead of only clearing content-drift `APLAN045`. Untracked live tasks carrying a
   retargeted explicit `trace_fingerprints` stamp were also skipped before checking their stamps.
3. **`aplan review` / `aplan_review` accepted tasks with mixed valid and dangling anchored traces
   (`A2-053`):** `aplan_core::review` refused only when `fingerprints.is_empty()`, so a task with
   one resolvable and one dangling anchored trace succeeded partially instead of refusing until
   every anchored trace resolves.
4. **Missing symmetric `row -> heading` `APLAN060` scenario in `coverage.rs` and idempotency /
   partial-dangling parity tests:** `crates/aplan-e2e/tests/coverage.rs` covered only
   `heading -> row`, and CLI/MCP parity did not yet exercise idempotent re-review or mixed
   valid+dangling trace refusal.

## Acceptance criteria

- [x] `table_rows()` in `crates/aplan-core/src/anchor.rs` skips leading YAML frontmatter and nested
      `---`-fenced metadata blocks identically to `headings()`, with a unit test pinning pipe
      scalars inside frontmatter and nested metadata
- [x] uncommitted `title`/`body`/`paths` edits on open tasks clear only `APLAN045` and never
      suppress blocking `APLAN060` retargeting unless `traces` itself was updated or confirmed via
      `aplan review`, and untracked live tasks with retargeted `trace_fingerprints` still report
      `APLAN060`
- [x] `aplan_core::review` (both CLI `aplan review` and MCP `aplan_review`) refuses live tasks
      when any declared anchored trace (`file#anchor`) fails to resolve, while continuing to allow
      file-only traces alongside valid anchored traces
- [x] `crates/aplan-e2e/tests/coverage.rs` includes symmetric `row -> heading` `Rule::TraceRetargeted`
      coverage (`docs/rule-catalogue.md` updated), and `drift.rs` + `mcp_parity.rs` pin idempotent
      re-review, mixed valid+dangling refusal, and uncommitted-body `APLAN060` persistence
