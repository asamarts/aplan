## Why

`aplan check --format agent` emits a JSON object, closes it, and then appends the important note
that `check` did not resolve repository evidence. A standard JSON decoder fails with `Extra data`,
so the format named for agents cannot be parsed as a document. One adopter worked around this by
truncating at the final brace, which is itself unsafe if the note changes.

The note must not disappear: it prevents a caller from reading a structural check as resolved
evidence. It belongs in the machine document, with one schema and one stream contract.

## Acceptance criteria

- [ ] every agent-format command emits exactly one valid JSON document on stdout
- [ ] the unchecked-evidence note remains machine-readable inside that document, with stable
      fields that do not require parsing English
- [ ] no human-only suffix or prefix can be appended to a machine-readable format by a shared
      rendering path
- [ ] tests parse the entire stdout to EOF and cover zero, one and many findings plus the note
- [ ] the correction to the existing format contract has a behaviour capability and proof
