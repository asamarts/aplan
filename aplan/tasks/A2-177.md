## Why

An independent review of the `A2-166` to `A2-168` fixes on 2026-11-18 found no defect in their
behaviour, but gaps in what proves it and in what the record says:

- The dependency audit compared only the declared requirement `=0.1.3`. A `[patch]` entry that
  points `ayaml` at a local copy keeps that requirement, so both the workspace and the TUI
  evaluator audits passed with a substituted parser, which `A2-166` says they refuse.
- The evaluator audit passes `--locked` so a stale lock fails, but no test failed with the flag
  removed.
- A `kep-number` wider than 64 bits was refused as "missing or not a number", which names neither
  the value nor the reason.
- The policy test's epoch predicate admitted any file named `M-`, where the matching predicate in
  `blueprint_examples.rs` admits only milestones.
- `docs/design/tui.md` said `A2-009` passed every readiness gate, where `yaml-parser.md` records
  gates 3 to 5 as met in part. The CHANGELOG's lists of who paid the ranking and cut-lookup costs
  named some commands that do not and missed some that do.

## Acceptance criteria

- [ ] both audits require the resolved `ayaml` to be 0.1.3 from crates.io, and tests fail for a
      local or different-version package under an unchanged requirement
- [ ] a test runs the evaluator audit on a workspace whose lock lacks a declared dependency and
      asserts the lock refusal, and the same workspace with a current lock gets past it
- [ ] the KEP importer names a `kep-number` wider than 64 bits and says why it is refused
- [ ] the policy test's epoch admits an `M-` task only if it is a milestone
- [ ] `docs/design/tui.md`, `docs/design/yaml-parser.md` and the CHANGELOG say what was measured
