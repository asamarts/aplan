## Why

An end-to-end audit of PRs #86-#88 (`f1d3503..e41ca8d`) identified five concrete gaps to close
before starting the `M-v0.8` build-contract implementation track:

1. **`workspace_root_for` substring match & missing real `build.rs` test:**
   `crates/aplan/build_support.rs` matched `root_manifest.contains("crates/aplan")`, which matches
   `"crates/aplan-core"` even when `"crates/aplan"` is not a member. Additionally, `build_identity.rs`
   unit-tested `collect_cache_identity_inputs` without driving the actual `crates/aplan/build.rs`
   script end to end against nested `tools/tui-eval/target/` artifacts.
2. **Remaining bind-mounted linked-worktree `.workdir()` callers:** `A2-192` fixed `version.rs`
   and `report_stale_premises`, leaving `aplan-app/src/claims.rs` (which fails `canonicalize` on a
   non-existent host workdir inside a container) and `summary --rev` in `crates/aplan/src/lib.rs`
   exposed. Centralizing `Repo::effective_workdir` (including walking ancestors for `.git` when
   invoked from a subdirectory inside a bind-mounted checkout) fixes every caller in one place.
3. **`ADR-0068` pre-release `requires.min_version` vacuity:** Allowing `-pre` strings like
   `"0.8.0-dev"` in `requires.min_version` would admit every `0.8.0-dev` build regardless of commit
   or capabilities. Tightening `requires.min_version` to bare release `X.Y.Z` only (refusing `-pre`
   values and pointing to `capabilities`/`source`/`facts_sha256`) closes that vacuous pin.
4. **Incomplete downstream task `paths` and sequencing (`A2-051`, `A2-053`, `A2-193`):**
   `A2-053` (`ADR-0070`) adds `aplan_review` (MCP), `close.rs` surgical writes, `docs/upgrading.md`,
   `HLD.md`, `AGENTS.md`, `cli-surface.json`, and builds on `ADR-0069`'s kind-tagged stamp format
   from `A2-051`, so it needs those `paths` and `blocked_by: [A2-052, A2-051]`. `A2-051` and
   `A2-193` likewise need their complete `paths` sets.

## Acceptance criteria

- [x] `workspace_root_for` checks exact `"crates/aplan"` / `'crates/aplan'` workspace membership
      rather than substring matching `crates/aplan-core`, and an executable test runs the real
      `build.rs` logic end to end proving nested `tools/tui-eval/target/` files leave
      `APLAN_CACHE_WRITER_IDENTITY` unchanged while product-source edits change it
- [x] `Repo::effective_workdir` centralizes bind-mounted linked-worktree resolution (including
      subdirectory `.git` ancestor discovery) across `version.rs`, `aplan-evidence/src/lib.rs`,
      `aplan-app/src/claims.rs`, and `crates/aplan/src/lib.rs`, with unit tests
- [x] `ADR-0068` and `A2-193.md` require `requires.min_version` to be a bare released `X.Y.Z`
      version (refusing `-pre` strings as vacuous pins)
- [x] `A2-051.md`, `A2-053.md`, and `A2-193.md` carry complete `paths` and `A2-053.md` sequences
      after `A2-051`
