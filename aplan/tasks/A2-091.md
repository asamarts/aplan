## Why

One adopting repository measured `APLAN019` against a task with two dead `paths` entries and one
live entry. The rule reported both dead entries when they were alone, then reported neither after
the live sibling was added. The dead entries did not change; the rule's task-level precondition
did. In a tiny plan, for a task that cites evidence:

```yaml
id: ABC-001
paths:
- src/gone_a.rs    # matches no tracked file
- src/live.rs      # matches a tracked file
- src/gone_b.rs    # matches no tracked file
```

Observed: `APLAN019` reports neither dead entry. Delete the `src/live.rs` line and it reports both.
Expected: both dead entries are reported either way.

That makes the rule loudest in the all-dead case, where `APLAN012` already refuses commit evidence,
and silent in the mixed case, where a typo narrows the task's evidence territory without being
reported. The adopter found 23 dead entries across seven tasks: ten entries across five tasks had a
live sibling and were therefore silent, including three of four entries on an eight-day task.

This widens what an existing rule detects, so it needs a `Behaviour` in the same commit and a proof
that distinguishes one dead entry from a whole dead list.

## Acceptance criteria

- [x] each dead `paths` entry on an evidence-bearing task is reported even when another entry
      matches, and the finding names only the entry the predicate judged
- [x] the historical-revision handling for terminal tasks remains intact
- [x] no-evidence tasks keep their current silence (the rule was deliberately narrowed to tasks that
      cite evidence, because a task with no evidence has nothing judged against its paths); the
      change does not restore the 140 speculative warnings one adopter saw for paths whose files
      had not been written yet
- [x] a regression test uses at least two path entries with the dead one not first, and the
      end-to-end fires/silent pair still states the rule's exact boundary
- [x] the widened existing behaviour has a capability name and executable proof
