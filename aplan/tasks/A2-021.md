## Why

Reported in #18. `APLAN045` (an open task's traced section changed since the task was last
touched) is silent when `traces_root` is left at its documented default `.`, and `verify`
exits 0. The same plan reports the drift once `traces_root: .` is written into
`.aplan.yml` or an absolute `--traces-root` is passed. A false pass: nothing tells the reader
the check compared nothing.

The cause is in `historical_trace_path` (`crates/aplan-evidence/src/lib.rs`): only an
absolute root is canonicalized and made repository-relative. A relative root is joined as
written, so `.`, `./docs`, `docs/.` and a root relative to a subdirectory produce a path such
as `./DOC.md` that matches no path in Git history, while a plain `docs` happens to work.

## Acceptance criteria

- [ ] the reproduction in #18 reports both `APLAN045` warnings under the default,
      `traces_root: .`, `--traces-root .`, `..` given from a subdirectory, and an absolute root
- [ ] `./docs` and `docs/.` resolve to the same history path as `docs`, covered by a fixture whose
      traced document is under `docs/`
- [ ] a regression test covers the relative and dotted forms through `verify`
- [ ] #18 is closed
