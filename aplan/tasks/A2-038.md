## Why

Reported in #34. When it was reported, type errors in the runner configuration named no key.
Since the parser switch (`A2-009`) they name the key path but describe the wanted shape in Rust
terms, checked on 2026-11-18:

- `test: runners[0].list: invalid type: string "true", expected a sequence`
- `test: schedule: invalid type: non-mapping YAML value, expected struct TestSchedule`

Runner validation names keys in the single-runner form even for a runner in a list: an empty
`run` at `test.runners[0]` reports `` `test.run` is an empty command ``. `test.run` is a real key
(the single-runner form), so the message is not wrong about the key existing; it is wrong about
where the value is.

## Acceptance criteria

- [x] every runner configuration type error says what shape it wants in configuration terms, for
      example `test.schedule: expected a mapping such as {capacity: 1}`
- [x] every runner validation error names the runner's own path, for example
      `test.runners[0].run`
