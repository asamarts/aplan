## Why

Reported in #24. `aplan inbox` documents newest-first order with the full id as tie-break.
`captured_at` has one-second resolution and the tie-break compares ids ascending, so captures
made within one second read oldest first inside a newest-first list. The ids are ULIDs, so a
descending tie-break is true time order to the millisecond.

## Acceptance criteria

- [x] the tie-break is descending, so captures from one second list newest first
- [x] `HLD.md` section 4, which says only "with full id as the tie breaker", states the direction
- [x] the `capture.rs` unit test that pins the ascending tie-break ("equal instants use full id
      ascending") asserts the descending one
- [x] a test captures several items within one second and asserts newest-first order
- [x] #24 is closed
