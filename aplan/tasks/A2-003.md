## Why

The first credential-free public full profile passed the authoritative nextest gate but exposed a
coverage-only timeout in
`tui_journey::diagnostic_workbench_runs_end_to_end_in_a_real_terminal`. The timeout capture already
showed the expected diagnostic detail. The journey had used `wait_until` for a compound whole-screen
assertion and sent the next key immediately; that API may return during a repaint, so the input could
race the screen transition under instrumented-suite contention.

## Acceptance criteria

- [x] the detailed diagnostic is captured only after the semantic sentinel is visible and the
      terminal has settled
- [x] every asserted field is checked against the captured screen before the journey sends its
      next key
- [x] the narrow coverage-instrumented journey passes repeatedly and the complete coverage and
      public validation profiles pass
