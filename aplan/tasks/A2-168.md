## Why

`Graph::task_rows` gave each task its cut by walking every non-borrowing cut and scanning its
members, once per task, so building the rows cost the number of tasks times the size of the
roadmap. `aplan show`, `aplan graph`, the MCP `show` tool and every TUI load and refresh build
them. A review of the `A2-018` change found it on 2026-11-18, beside the quadratic ranking pass
that change removed.

The answer must not change: the first cut in roadmap order that names a task, as its milestone
or a member, owns it; a release never does, because it borrows its cuts' members (`A1-240`), and
a container never does (`A1-333`).

## Acceptance criteria

- [ ] the rows read one map built in a single pass over the cuts
- [ ] a test holds the map to the per-task walk on a plan with a release, a container, a nested
      cut, a task two cuts list, a milestone another cut lists and a task no cut names, and fails
      if borrowed rows are read or a later cut wins
