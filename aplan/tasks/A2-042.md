## Why

Reported in #19. `aplan close --evidence note:...` and `amend --add-evidence note:...` are
refused because a note needs a `captured` date that the tool will not invent, and the message
sends the user to edit the file by hand, outside the commands that validate a citation. MCP
`aplan_close` refuses a note the same way. The public record gives one reason, that the tool must
not invent the date: HLD.md says the author or importer sets `captured`, `docs/upgrading.md` says
`aplan close` does not invent human provenance, and the MCP close tool says an agent that wants a
note writes it by hand, where a human sees the date it claims. The TUI close form already records
a note with a date its author supplies. The report proposes `--captured YYYY-MM-DD`, supplied by
the caller, so nothing is read from the clock.

Untestable: a decision record.

## Acceptance criteria

- [ ] a decision is recorded on whether `close`, `amend` and MCP `aplan_close` accept a
      caller-supplied captured date for note evidence, consistent with the TUI's dated note
- [ ] the implementation task's criteria match the decision, or it is dropped with the reason
