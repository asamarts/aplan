## Why

An ordinary attempt to close an already-done task already names the exact `amend --add-evidence`
recovery, and top-level help describes every amendment mode. Neither covers the command an auditor
tries first when both the citation and its fingerprinted referent changed: `close --restamp
--evidence`. Clap correctly refuses those mutually exclusive operations, but the conflict output
and `close --help` expose neither the sibling `amend` operation nor the safe order.

Two adopting repositories hit this discovery failure after the already-done recovery shipped: one
reproduced it twice, and the other needed two refusals to find the same `amend`, then `close
--restamp` sequence. Keep the two mutations distinct: changing citations and asserting that current
trace/file content still proves a completed task are different claims. Make their composition
discoverable at the exact entry point where users currently guess a combined close command.

Generic reproducer: a done task `ABC-001` whose traced section was edited and which needs one more
citation.

```console
$ aplan close ABC-001 --restamp --evidence test:suite::new_case
```

Observed: only Clap's generic argument-conflict refusal. Expected: the refusal also names
`aplan amend ABC-001 --add-evidence test:suite::new_case` followed by `aplan close ABC-001
--restamp`.

One adopter later found the adjacent recovery path after a successful close: rebasing before the
push rewrites the implementation commit while the task keeps citing the old object. Reachability
verification now refuses that orphan locally, but the refusal and command help must lead directly
to `amend --replace-evidence commit:OLD commit:NEW`; otherwise the stronger gate converts a
post-rebase repair into another command-discovery exercise.

## Acceptance criteria

- [ ] `close --help` explains that a done task's citation changes use `amend` and that changed
      citations and fingerprint restamping are two ordered, separately gated operations
- [ ] an attempted `close --restamp --evidence ...` refusal names an executable recovery using
      `amend --add-evidence` followed by `close --restamp`, without accepting the invalid combined
      mutation or changing repository state
- [ ] replace and remove evidence remain discoverable without making the common add path verbose,
      and ordinary first closure plus already-done refusal behavior remains unchanged
- [ ] an orphaned commit citation after a rebase is refused locally and its recovery names the
      exact `amend --replace-evidence commit:OLD commit:NEW` invocation without suggesting removal
      or weakening reachability
- [ ] a command-driven test follows the rendered recovery against a done task whose evidence and
      traced content both changed, then proves the added citation resolves and the new fingerprint
      clears drift
- [ ] help, color/no-color, narrow-terminal and hostile task-id rendering stay bounded and do not
      permit task or citation text to inject terminal controls or command syntax
