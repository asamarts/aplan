## Why

Reported in #35. The Action's install step downloads the release once, so a single HTTP 5xx
or network error from GitHub fails the consumer's job before any plan check runs, and the
failure reads like a failed plan gate. Re-running the job is the only remedy.

## Acceptance criteria

- [x] the download retries a small fixed number of times with a short backoff on a 5xx or a network
      error
- [x] a 404, a checksum mismatch or a provenance failure is never retried
- [x] a final failure says the install failed and no plan check ran
- [x] the Action self-test still passes, and #35 is closed
